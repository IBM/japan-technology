# 3. アーキテクチャー概要
シナリオを解決するAIエージェントを構築してみましょう。

## 3-1. シナリオ
**ペルソナ：アリスさん（30歳・法人営業）**
- 急な海外出張が多い
- 最適なフライトを素早く見つけたい

```
シアトル出張が決定
　→ 出張エージェントが条件を確認
　→ 便を比較（価格・時間）
　→ 最適便を選択
```

## 3-2. 出張エージェントの役割

| 機能 | 内容 |
|------|------|
| 情報収集 | 出発地・目的地・日程・予算などの必要情報を収集する |
| 候補整理 | フライト候補を一覧化・比較しやすく整理する |
| 提案 | 条件に最適な選択肢を提示する |
| 予約サポート | 予約・変更・キャンセルの手続きを支援する |


## 3-3. 全体構成
```
親エージェント
└── 出張コンシェルジュ
    ├── ✈️  フライト専門エージェント
    │       フライト検索・予約・変更・キャンセルを担当
    │       4 つの専用ツールを保有
    └── 🏨  ホテル専門エージェント
            ホテル・アクティビティ・予算を担当
            （フライト専門エージェントと同じパターンで構築可能）
```

> 💡 **今日のスコープ**：フライト専門エージェントを中心にストーリーを進めます。ホテルやその他のユースケースも、同じパターンで構築できます。


### 3-3-1. 親エージェント（オーケストレーター）の動作
1. ユーザーからのリクエストを受け取る
2. リクエストを分解し、適切な専門エージェントへルーティングする
3. 複数の専門エージェントのレスポンスを統合してユーザーへ返す
4. 一般的なクエリは直接処理する


### 3-3-2. マルチエージェントアーキテクチャー
本ハンズオンでは、**1 つの親エージェントが複数の子（専門）エージェントを束ねる** アーキテクチャーを採用します。

シングルエージェントにすべての機能を詰め込む設計には、現実的な限界があります。
マルチエージェント設計に移行することで、その問題を解消できます。


#### シングルエージェントの問題点

| 問題 | 内容 |
|------|------|
| 圧倒的な複雑さ | ツール数が 50 以上、指示が 1,000 行を超えると保守が困難になる |
| パフォーマンス低下 | 多くの責務を持つエージェントは、専門タスクへの精度が下がる |
| テスト・デバッグが困難 | 問題の切り分けができず、バグの特定に時間がかかる |

#### マルチエージェントのメリット

| メリット | 内容 |
|----------|------|
| 関心の分離 | 各エージェントが 1 つの責務に集中するため、設計がシンプルになる |
| 高いパフォーマンス | 専門タスクへの精度・品質が向上する |
| 保守性の向上 | 個別のエージェントを独立して更新・テストできる |
| 再利用性 | スペシャリストを他のシステムやシナリオでも再利用できる |
| スケーラビリティ | システムの成長に合わせて新しい専門エージェントを追加できる |


### 3-3-4. エージェントの階層化
マルチエージェントシステムでは、**親エージェント（オーケストレーター）** と **子エージェント（スペシャリスト）** が明確な役割分担を持ちます。


#### 親エージェントの役割

- 適切なスペシャリストへリクエストをルーティングする
- 会話全体のフローを管理する
- 複数エージェントのレスポンスを統合する
- 一般的なクエリを直接処理する

#### 子エージェント（専門エージェント）の役割

- 特定ドメインの深い専門知識を持つ
- フォーカスされたツールと知識のみを保有する
- 明確で具体的な指示に従って動作する
- タスク完了後はオーケストレーター（親エージェント）へ結果を返却する

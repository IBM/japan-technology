# Project 7: 仕様駆動開発とコンテナデプロイ
- 対象者: Python と 生成AIフレームワークの基礎知識を持つ開発者、コンテナ技術とクラウドデプロイに興味がある方

## 概要
このハンズオンでは、**仕様駆動開発** を使用して生成AIアプリケーションを開発し、それをコンテナ化して本番環境にデプロイするまでの一連のプロセスを学習します。

PDF の請求書ファイルを処理し、抽出された結果を表形式およびグラフ形式で表示する機能を実装します。開発したアプリケーションは、再利用可能なコンポーネントとして設計され、より大規模なシステムに統合できるようになっています。

主な内容には、オープンソース API と統合された生成AIアプリケーションコンポーネントの開発、開発したアプリケーションの Docker コンテナ化、ローカル環境および IBM Cloud Code Engine へのデプロイが含まれます。

## 目的
- 仕様駆動開発により、明確な仕様から実装可能なコードを生成する
- 複数ベンダーが提供する API を横断的に統合・オーケストレーションする
- アプリケーションを Docker コンテナ化し、本番環境にデプロイする
- Bob を活用した効率的な開発とトラブルシューティングを体験する

- 想定所要時間: 2〜3時間

## 状況の想定
あなたは、複数ベンダーの API を統合した生成AIアプリケーションを開発し、本番環境にデプロイする開発者です。Bob を活用しながら、仕様書の作成、コード生成、テスト、コンテナ化、デプロイまでを進めます。実務に近い流れの中で、Bob を使った開発支援の進め方を体験することが目的です。

## 本ハンズオンを開始する前に
- 必須
  - IBM Bob が利用可能な状態であること
  - Git（Bob から使用する場合はコマンドライン、または GitHub Desktop）
  - Bob 用 Python 拡張機能
  - Python ランタイム（バージョン 3.12 または 3.13）
  - watsonx.ai へのアクセス（LLM 推論用。手順は本ドキュメント内で提供されます）
- デプロイ環境に応じて必要
  - ローカルのコンテナプラットフォーム（IBM により承認されたもの。例：Podman Desktop, Rancher など）
  - IBM Cloud へのアクセス（Code Engine へのデプロイに使用）
- 補足
  - 必要な Python パッケージは、コード生成後に Bob がインストール対象の一覧を作成します
  - 詳細なセットアップや操作手順は、各フェーズの手順に従ってください

## 注意事項

> ⚠️ **Windows 環境での注意：** Windows 環境で Windows Subsystem for Linux（WSL）を使用する場合、30～40GB 程度のディスク容量が消費される可能性があります。このディスク容量を解放するには、特定のコマンドを実行してクリーンアップを行う必要があります。




## 手順

### フェーズ 1：アプリケーション開発

#### 1. リポジトリの取得
Bob を使用して、ドラフト仕様および請求書データを含む Git リポジトリを取得します。
- Bob はシェル／コマンドウィンドウでコマンドを実行できます。
- Git を Bob から使用する前に、Git リポジトリへの接続設定を行ってください。
- プロンプト例: `<repo_url> をこのフォルダにダウンロードしてください`

#### 2. 仕様のレビューと改善
ドラフト仕様ファイルを確認し、必要に応じて変更します。
- Bob にドラフト仕様（draft_spec.txt）を改善させます。
- UI の簡単なイメージ図を含めても構いません。
- プロンプト例: `draft_spec.txt にあるアプリケーション開発仕様を改善してください。結果を master_spec.md として保存してください。`

#### 3. 最終仕様レビュー
生成された仕様書を確認し、必要に応じて修正します。

#### 4. コード生成
仕様書からコードを生成し、生成されたコードをレビューします。
- 必要に応じて、初期コードの一部を再生成するよう Bob に依頼できます。

#### 5. 実行設定の確認
アプリケーション実行に必要な設定手順を確認します。
- 不明点があれば Bob に質問します。

#### 6. API キーの生成
watsonx.ai にログインし、Welcome ページの「Developer Access」セクションで **「Create API key」** をクリックして API キーを生成します。

#### 7. 設定の反映
`.env` ファイルに必要な設定値を入力します。

#### 8. テスト
各モジュールごとにユニットテストを生成することも可能です。または、まずアプリケーション全体をまとめてテストしても構いません。
- トラブルシューティングの選択肢：
  - Bob を使って問題解決を試みる
  - 新しい仮想環境を作成して Python プロジェクトを実行する

#### 9. 実行と最終確認
アプリケーションを実行し、手動テストを行います。

Bob に以下の点についてアドバイスを求めることができます：
- テスト
  - プロンプト例: `手動テストは完了しました。今後の変更に備えて自動テストを導入するにはどうすればよいですか？`
- セキュリティレビュー
  - プロンプト例: `このアプリケーションのセキュリティレビューを実施してください。`
- デプロイ方法
  - プロンプト例: `このアプリケーションを Podman 上のローカルコンテナおよび IBM Cloud にデプロイしたいです。手順を説明してください。`

### フェーズ 2：コンテナ化とデプロイメント

アプリケーションの開発とローカルテストが完了したら、次はコンテナ化してデプロイします。

#### 重要：セキュリティの考慮事項
フェーズ 1 では、API キーを環境ファイル（`.env`）に保存しました。これはデスクトップ上でプロトタイプを開発する際によく用いられる方法です。しかし、アプリケーションをデプロイする場合には、より安全な方法を実装する必要があります。このフェーズでは、その点も考慮したデプロイを行います。

#### 1. デプロイ戦略の策定
Bob に対して、コンテナ・デプロイの方法についての推奨事項を問い合わせます。
- Bob に指示する際は、以下の点を明確に伝えてください：
  - ローカルコンテナ環境と IBM Code Engine の両方にデプロイしたいこと
  - 同じコードベースを維持するかどうかを決めること
  - セキュリティベストプラクティス（環境変数、シークレット管理など）を適用すること
- プロンプト例: `このアプリケーションをローカルコンテナ（Podman）と IBM Cloud Code Engine の両方にデプロイしたいです。セキュリティベストプラクティスを考慮した Dockerfile と必要な設定ファイルを生成してください。`

#### 2. Dockerfile とデプロイ設定の生成
Bob が以下のファイルを生成します：
- `Dockerfile`：コンテナイメージのビルド定義
- `docker-compose.yml`（オプション）：ローカル開発用
- `.dockerignore`：不要なファイルの除外設定
- デプロイ手順書：ステップバイステップのデプロイガイド

#### 3. ローカルコンテナでのテスト
まず、ローカル環境でコンテナが正しく動作することを確認します。
- 実施内容：
  - コンテナイメージのビルド
  - ローカルでのコンテナ起動
  - 機能テストの実施
  - ログとエラーの確認
- ヒント：
  - 1つのステップに集中して進めてください
  - 問題が発生した場合は Bob を使ってトラブルシューティングしてください
  - Bob 上でコマンドを実行するか、ターミナルを使うかを試してください

#### 4. IBM Cloud Code Engine へのデプロイ
ローカルテストが成功したら、IBM Cloud Code Engine にデプロイします。
- 実施内容：
  - IBM Cloud CLI のセットアップ
  - Code Engine プロジェクトの作成
  - シークレット（API キーなど）の設定
  - アプリケーションのデプロイ
  - 本番環境での動作確認
- プロンプト例: `IBM Cloud Code Engine へのデプロイ手順を教えてください。API キーは環境変数として安全に設定したいです。`

#### 5. デプロイ後の確認とモニタリング
デプロイが完了したら、以下を確認します：
- アプリケーションの正常動作
- ログの確認
- パフォーマンスのモニタリング
- エラーハンドリングの検証

## トラブルシューティング

### よくある問題と解決策

**問題 1：コンテナビルドエラー**
- 依存関係の問題：`requirements.txt` を確認
- ベースイメージの問題：Python バージョンを確認
- Bob に具体的なエラーメッセージを共有して解決策を求める

**問題 2：環境変数が認識されない**
- `.env` ファイルの配置場所を確認
- Docker / Code Engine での環境変数設定方法を確認
- Bob にデプロイ環境に応じた設定方法を問い合わせる

**問題 3：ポート接続エラー**
- Dockerfile の EXPOSE 設定を確認
- Code Engine のポート設定を確認
- ファイアウォール設定を確認

# ゼロからアプリを作り切る「開発・テスト完全攻略」割り勘アプリ編（55分）

今日は **コードを1行も書きません**。あなたがやるのは「どう動いてほしいか」を日本語で決めることだけ。コードにするのは IBM Bob、正しく動いたかを確かめるのは自動テストです。

> この文書は guide.html と同じ内容の Markdown 版です。Bob に送る文はコピーボタン付きの guide.html のほうが使いやすいので、ふだんは guide.html を統合ブラウザーで開いてください。

## 地図 — 触るファイルは 4 つ、回るのは 1 つの輪

- `index.html` — **画面**（Bob が作る）
- `logic.js` — **計算**（Bob が作る）
- `tests.js` — **期待値**（あなたが決め、Bob が書く）
- `test.html` — **採点機**（開くだけ（主催者が用意））

- **① 決める** cases.html の表を電卓で埋める
- **② Bob が書く** このガイドの文をコピーして送り、承認する
- **③ 採点機で見る** test.html を再読み込み
- **④ 赤なら貼る** 「結果をコピー」→ Bob に貼る → ② へ

その他のファイル: `spec.md`（仕様書）、`cases.html`（テストケース記入表。ブラウザーで開いて入力）、`cases.md`（同じ表の文字版。使わなくてOK）、`spec-change.md` / `spec-change-2.md`（仕様変更票。合図まで開かない）、`harness.js` / `AGENTS.md`（裏方。触らなくてOK）。

> **皆さんにお願いしたいこと**
> 1. **期待値は自分の電卓で。** Bob に答えを出させると、Bob の答えを Bob で確かめることになります。
> 2. **承認は中身をひと目見てから。** Bob はファイルを書き換える前に毎回聞いてきます。
> 3. **赤を怖がらない。** テストの赤は「期待とのズレが見えた」合図です。
> 4. **困ったら 30 秒で手を挙げる。** チャットに「ステップ○で止まった」と書けば、完成版ファイルを渡して先に進めます。

## ステップ0 準備（0:06〜0:09）

1. 配布された zip を展開します（デスクトップなど分かりやすい場所に）。Windows: 右クリック →「すべて展開」／ Mac: ダブルクリック
2. IBM Bob を起動し、**［ファイル］→［フォルダーを開く］** で展開した `warikan-starter` フォルダーを開きます。「このフォルダーの作成者を信頼しますか」と聞かれたら **信頼する**。
3. 右側の Bob のチャット欄（入力欄の左下）が **Agent** モードになっていることを確認します。
4. Bob の左側のエクスプローラーで `test.html` を**右クリック →「統合ブラウザーで開く」**。Bob の中にブラウザーが開き、**「テストがまだありません」** と表示されれば準備完了。このタブは閉じずに残します。
5. 同じ操作で `cases.html`（テストケース記入表）も右クリック →「統合ブラウザーで開く」で開いておきます。ステップ2 から使います。
6. チャットに「○」と書いてください。

> アドレス欄が `file:///…/test.html` で始まっていればOK。インターネットは使いません。以降「再読み込み」と書いてあるところは、統合ブラウザーのアドレス欄左にある **⟳** ボタンを押します。ふだんのブラウザー（Chrome / Edge / Safari）で開きたい場合は、エクスプローラー（Mac は Finder）で `test.html` をダブルクリックしても同じです。

## ステップ1 アプリを作る（0:09〜0:15）

Bob のチャット欄に、次の文を送ります（右のアイコンでコピーできます）。

**Bob に送る文**（そのままコピーして Bob のチャット欄に貼る）

```text
spec.md と AGENTS.md を読んで、割り勘アプリを index.html と logic.js に実装してください。
```

- Bob は最初に「ファイルを読んでよいか」を聞いてきます。1回目は **「タスクの read ツールを承認」** を押すと、以後は聞かれなくなります。
- ファイルを**書き換える**前の確認は、毎回内容をざっと見て **「一度だけ承認」**（今日は合計 10 回くらい押します）。
- チャットの上のほうに「○個のファイルを変更 … すべて元に戻す」という帯が出ますが、**押さない**でください（Bob の変更が全部巻き戻ります）。
- 終わったら、`index.html` も同じように右クリック →「統合ブラウザーで開く」で開き、「計算する」を押してみます。
- 次に **合計金額 10000・人数 3** で計算してみてください。何が表示されましたか？

> **ここで「あれ？」と思ったことが、次のステップの材料です。**
> 表示された金額を 3 人分集めたら、ぴったり 10,000 円になりますか？

## ステップ2 「正しい答え」を先に決める（0:15〜0:22）

1. Bob のエクスプローラーで `cases.html` を右クリック →「統合ブラウザーで開く」。**表A** の端数のルールをチームで決め（1円未満をどうするか、余りはどうするか）、空欄に数字を入れます。期待する金額は **自分で** 電卓で出してください。
2. 表A の下の **「Bob に送る文を作る（テストだけ追加）」** を押し、できた文を **「コピー」** → Bob のチャット欄に貼り付けて送ります。文の中に表とお願いが入っているので、他に書き足すことはありません。

> できる文はこんな形です（表の中身はあなたの入力で変わります）:
> `次の表A を tests.js にテストとして追加してください。まだ logic.js は直さないでください。`＋ 表A

3. `test.html` を**再読み込み**します（統合ブラウザーの ⟳。ふだんのブラウザーなら F5 / ⌘R）。赤くなった行が「今のアプリが期待どおりでないところ」です。Bob が「失敗するはず」と先に言っていても、本当かどうか自分の目で確かめましょう。
4. test.html の **「結果をコピー」** ボタンを押し、Bob のチャット欄に貼り付けてから、続けて次の文を貼ります。

**結果の後ろに続けて送る文**（そのままコピーして Bob のチャット欄に貼る）

```text
test.html で全部○になるように logic.js と index.html を直してください。tests.js の期待値は変えないでください。テストの実行は私がやります。
```

5. `test.html` を再読み込みして、**全部 ○** になるまで 3〜4 を繰り返します。
6. **画面でも確かめます。** `index.html` を再読み込み（⟳）して **10000円・3人** で計算し、表A に書いた期待値（3,334円・余り 2円）と同じ表示になっているか見てください。

> テストが見ているのは `logic.js`（計算）だけです。画面（`index.html`）はテストが見ていないので、毎回 **目で** 確かめます。あなたが決めた期待値が、そのまま検査装置になりました。

## ステップ3 仕様変更に強くなる（0:22〜0:29）

講師の合図があったら `spec-change.md` を開きます。「幹事ルール」を追加します。**今度は先にテストから** 書きます。

1. `cases.html` の **表B**（見出しをクリックすると開きます）の空欄を埋めます（電卓で）。
2. 表B の下の **「Bob に送る文を作る（テストだけ追加）」** → **「コピー」** → Bob に貼り付けて送ります。

3. `test.html` を再読み込み → 表B の行が赤、**表A の行は ○ のまま**であることを確認します。
4. Bob に送ります。

**Bob に送る文**（そのままコピーして Bob のチャット欄に貼る）

```text
spec-change.md のとおりに logic.js と index.html を変更してください。test.html で全部○になるのが目標です。テストの実行は私がやります。
```

5. `test.html` を再読み込み → 全部 ○ になればクリア。**表A の行が1つでも赤になっていたら**、それは「仕様変更で昔の動きが壊れた」サインです。結果をコピーして Bob に直させましょう。
6. **画面でも確かめます。** `index.html` を再読み込みし、「端数処理の単位」と「幹事が端数を引き受ける」が画面に増えているか、**12345円・5人・100円単位・幹事あり** で 幹事以外 2,400円／幹事 2,745円 と出るかを見ます。画面に項目が無ければ、テストは緑でも仕様変更は終わっていません。Bob に「spec-change.md の画面の変更（単位の選択と幹事のチェック）が index.html に入っていません」と伝えます。

> ⚠ Bob が「コマンドを実行」や「Browser Navigate」の承認を求めてきたら **「拒否」** を押してください。テストを動かすのはあなたの役目です（Bob が自分で動かそうとしているだけで、壊れてはいません）。

## ステップ4 自分のルールを足す（0:29〜0:40）

講師の合図があったら `spec-change-2.md` を開きます。候補 A（クーポン）/ B（最低支払額）/ C（学生は半額）から **チームで 1 つ選びます**。どの候補にも「決めること」が 1 つ残っています。**まずそれを決めて**、`cases.html` の **表C** の「決めたこと」欄に書いてください。

1. `cases.html` の表C で「選んだ候補」を選び、「決めたこと」を書き、表を埋めます。No.3 には「決めたこと」が効く値を必ず入れます。期待値は電卓で。
2. 表C の下の **「Bob に送る文を作る（テストだけ追加）」** → **「コピー」** → Bob に貼り付けて送ります（候補と「決めたこと」も文に入ります）。

3. `test.html` を再読み込み → 表C が赤、表A・表B は ○ のまま。
4. Bob に送ります。

**Bob に送る文**（そのままコピーして Bob のチャット欄に貼る）

```text
spec-change-2.md の採用した候補と、さっき追加した表Cのテストのとおりに logic.js と index.html を変更してください。test.html で全部○になるのが目標です。テストの実行は私がやります。
```

5. `test.html` を再読み込み → 全部 ○ でクリア。Bob が「決めること」について質問してきたら、表C に書いた答えをそのまま返します。
6. **画面でも確かめます。** `index.html` を再読み込みし、選んだ候補の入力欄が増えているか、表C の No.1 と No.3（「決めたこと」が効く値）を入れて期待どおりに出るかを見ます。

> ここが今日いちばん「開発者っぽい」工程です。ルールの穴を見つけて、決めて、期待値にして、AI に渡す。全部人間の仕事です。

## ステップ5 バグ探しクイズ（0:40〜0:44）

講師が「壊れた logic.js」を 3 本（A・B・C）使って test.html を動かした結果を画面に出します。**どのテストが落ちたかだけを見て**、どこが壊れているかをチャットで当ててください。コードは読まなくて大丈夫です。

ヒント: 落ちたテストの共通点は？ 期待と実際の差はいくつ？ 落ちなかったテストは何を意味する？

> 自分の手元でもやってみたい人は、`logic.js` を `logic-mine.js` という名前でコピーしてから、配られた壊れ版と入れ替えてください（表C は赤になりますが無視して OK。終わったら戻します）。

## ステップ6 リバース・エンジニアリング演習（0:44〜0:51）

ここまで、あなたはコードを 1 行も読んでいません。今あるコードが「何を決めているか」を Bob に説明させます。読むだけなので承認は出ません。

**問い 1**（そのままコピーして Bob のチャット欄に貼る）

```text
test.html と harness.js と tests.js がどう組み合わさって ○× を出しているか、プログラミングを知らない人向けに 5 行以内で説明してください。
```

**問い 2**（そのままコピーして Bob のチャット欄に貼る）

```text
logic.js を読んで、計算ルールを spec.md と同じ見出しの仕様書の形で書き出してください。そのうえで、spec.md・spec-change.md・spec-change-2.md のどこにも書いていないのに logic.js が決めていることを、別に箇条書きにしてください。
```

2 つ目の答えの「書いていないのに決めていること」を 1 つ選んで考えます。**それは誰が決めましたか？ テストに書いてありますか？**

> 動いているコードから仕様を取り戻す作業を「リバース・エンジニアリング」と呼びます。古いシステムの改修でいちばん難しいのは、この「書いていないのに決まっていること」です。

## 困ったとき

| 症状 | 対応 |
|---|---|
| test.html が「読み込みエラー」になった | 赤い枠のメッセージをコピーして Bob に貼り、「このエラーを直して」 |
| Bob の返事が止まった／変なことをし始めた | チャットの停止ボタンを押し、同じ依頼をもう一度短く送る |
| 再読み込みしても変わらない | Bob が本当にファイルを保存したか確認（タブ名に ● が付いていたら未保存）。別フォルダーの test.html を開いていないかアドレス欄を確認 |
| Bob が tests.js の期待値を書き換えて「通した」と言う | 「tests.js を元に戻して、logic.js の方を直して」と送る（答案を書き換えて合格、はダメ） |
| 「すべて元に戻す」を押してしまった | 講師に声をかけてください。そのステップの完成版ファイルを渡します |
| どうにもならない | チャットに「ステップ○で止まった」。完成版を上書きして次に進めます |

## 早く終わった人へ（発展カード）

- 表C の 2 つ目: 残りの候補をもう 1 つ足す。2 つのルールが**同時に**効くとき（クーポンあり＋学生あり など）の期待値を先に決めてから。
- 「1 円単位で割って余りが出たら、誰が払う？」を仕様にする。「余りをランダムに 1 人に乗せる」はテストできる？ できないならなぜかを Bob に聞いてみる。
- tests.js の中を Bob に説明させる:

**発展**（そのままコピーして Bob のチャット欄に貼る）

```text
tests.js の 1 行目のテストが何を確かめているか、小学生にも分かるように説明してください。
```

## 今日のまとめ（自分の言葉で）

- 期待する答えを先に決めると、何が得だった？
- 仕様変更のとき、古いテストは何をしてくれた？
- テストが「赤」になるのは、悪いこと？
- 「書いていないのに決まっていること」は、誰が決めた？

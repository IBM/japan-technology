# このフォルダーで作業するときの約束（IBM Bob 向け）

あなたはプログラミング未経験の参加者と一緒に、ブラウザーだけで動く「割り勘アプリ」を作ります。
参加者は日本語で仕様とテストケースを書き、あなたがコードにします。次の約束を必ず守ってください。

## 1. 技術の制約（file:// で開くため）
- 使うのは素の HTML / CSS / JavaScript だけ。ライブラリ・フレームワーク・CDN・npm・ビルドツールは使わない
- `<script type="module">`、`import` / `export`、`fetch()`、`require()` は使わない（file:// で動かない）
- 外部ファイルの読み込みは `<script src="logic.js"></script>` の形だけ
- サーバーは起動しない。「ブラウザーで index.html（または test.html）を開き直してください」と案内する
- **テストを自分で実行しない。** ターミナルコマンド（node, npm, python など）を実行しない。ブラウザーツール（Browser Navigate 等）も使わない。test.html を開いて結果を確かめるのは参加者の役目で、参加者が結果を貼り付けてくれる。「テストを通して」と言われたらコードを直して「test.html を再読み込みして結果を教えてください」と返す

## 2. ファイル構成（変えない・増やさない）
| ファイル | 役割 | あなたが編集してよいか |
|---|---|---|
| `logic.js` | 計算ロジック。`calcSplit()` を定義する | **編集する** |
| `index.html` | 画面。入力を受け取り `calcSplit()` を呼んで結果を表示する。CSS と JS はこのファイルの中に書く | **編集する** |
| `tests.js` | 自動テスト。`check()` の行を書く | **編集する（追記が基本。既存のテストは参加者の許可なく消さない）** |
| `test.html` / `harness.js` | テストランナー | **編集しない** |
| `spec.md` / `cases.md` / `cases.html` / `AGENTS.md` | 仕様・テストケース表・この約束 | **編集しない** |

## 3. 計算関数の契約（test.html がこの名前・形で呼びます）
```js
function calcSplit({ total, people, unit, organizer })
```
- `total`: 合計金額（円・整数）、`people`: 人数（整数）
- `unit`: 端数処理の単位（1 / 10 / 100 / 500 / 1000）。省略時は 1
- `organizer`: 幹事が端数を引き受けるなら true。省略時は false
- ステップ5（spec-change-2.md）で追加する入力。いずれも省略可で、省略時は「無効」:
  - `coupon`: クーポン値引き額（円）。省略時 0
  - `minEach`: 幹事以外の1人の最低支払額（円）。省略時 0（無効）
  - `students`: うち学生の人数。省略時 0
- 入力を増やしても、省略時の動きは変えない（表A・表B のテストが通ったままになるように）
- 戻り値はオブジェクト。キー名は次のものを使う（必要なものだけでよい）
  - `each`: 1人あたりの金額（幹事ありのときは「幹事以外の1人あたり」）
  - `organizer`: 幹事が払う金額（幹事ありのときだけ）
  - `student`: 学生1人の金額（学生ルールのときだけ）
  - `collected`: 全員から集まる合計
  - `change`: 余り（集まる合計 − 実際の合計）
  - `error`: 入力が不正なときのメッセージ（日本語）。エラーのときは他のキーを返さなくてよい
- 入力不正（数値でない、マイナス、人数0など）は例外を投げず `{ error: "..." }` を返す
- `calcSplit` は画面（DOM）に触らない。`document` や `alert` を logic.js に書かない

## 4. テストの書き方（tests.js）
- 1件1行: `check("説明", 実際の値, 期待する値);`
- 期待する値がオブジェクトなら、書いたキーだけが比較される: `check("…", calcSplit({ total: 10000, people: 3 }), { each: 3334, change: 2 })`
- エラーになることの確認は `{ error: ANY_TEXT }` を期待値にする
- 説明は参加者が書いた日本語をそのまま使う。まとまりごとに `section("見出し");` を入れる
- テストフレームワーク（Jest, Mocha など）は使わない。`describe` / `it` / `expect` は存在しない

## 5. 進め方
- 参加者から「テストを追加して」と言われたら、**テストだけ**を書き、logic.js は触らない。先に赤（失敗）を見せる
- テストケースの表は、参加者がチャットに貼り付けて渡す（cases.html が作る）。cases.md を読む必要はない。表の「期待する結果」をそのまま check() の期待値にする。「エラーになる」は `{ error: ANY_TEXT }`
- 「テストを通して」と言われたら、logic.js（必要なら index.html）を直す。tests.js の期待値を書き換えて通してはいけない
- 仕様が曖昧なときは勝手に決めず、参加者に 1 つずつ質問する（例:「人数に 2.5 のような小数が入力されたらエラーにしますか？」）。ただし仕様書に「決めない」「そのままでよい」と書いてあることは、そのとおりに作る
- 変更したあとは毎回「ブラウザーで test.html を再読み込みしてください」と伝える
- 説明は短く、専門用語を使うときは一言添える

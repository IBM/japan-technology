皆さんにお願いしたいこと

  1. 期待値は自分の電卓で。 Bob に答えを出させると、Bob の答えを Bob で確かめることになります。
  2. 承認は中身をひと目見てから。 Bob はファイルを書き換える前に毎回聞いてきます。
  3. 赤を怖がらない。 テストの赤は「期待とのズレが見えた」合図です。
  4. 困ったら 30 秒で手を挙げる。 チャットに「ステップ○で止まった」と書けば、完成版ファイルを渡して先に進めます。

0準備0:06〜0:09

  1. 配布された zip を展開します（デスクトップなど分かりやすい場所に）。Windows: 右クリック →「すべて展開」／ Mac: ダブルクリック
  2. IBM Bob を起動し、［ファイル］→［フォルダーを開く］ で展開した warikan-starter フォルダーを開きます。「このフォルダーの作成者を信頼しますか」と聞かれたら 信頼する。
  3. 右側の Bob のチャット欄（入力欄の左下）が Agent モードになっていることを確認します。
  4. Bob の左側のエクスプローラーで test.html を右クリック →「統合ブラウザーで開く」。Bob の中にブラウザーが開き、「テストがまだありません」 と表示されれば準備完了。このタブは閉じずに残します。
  5. 同じ操作で cases.html（テストケース記入表）も右クリック →「統合ブラウザーで開く」で開いておきます。ステップ2 から使います。
  6. チャットに「○」と書いてください。
アドレス欄が file:///…/test.html で始まっていればOK。インターネットは使いません。以降「再読み込み」と書いてあるところは、統合ブラウザーのアドレス欄左にある ⟳ ボタンを押します。ふだんのブラウザー（Chrome / Edge / Safari）で開きたい場合は、エクスプローラー（Mac は Finder）で test.html をダブルクリックしても同じです。

Bob に送る文
spec-change.md のとおりに logic.js と index.html を変更してください。test.html で全部○になるのが目標です。テストの実行は私がやります。
  1. test.html を再読み込み → 全部 ○ になればクリア。表A の行が1つでも赤になっていたら、それは「仕様変更で昔の動きが壊れた」サインです。結果をコピーして Bob に直させましょう。

4自分のルールを足す0:29〜0:40

  2. 表C の下の 「Bob に送る文を作る（テストだけ追加）」 → 「コピー」 → Bob に貼り付けて送ります（候補と「決めたこと」も文に入ります）。
  1. test.html を再読み込み → 表C が赤、表A・表B は ○ のまま。
  2. Bob に送ります。
Bob に送る文
spec-change-2.md の採用した候補と、さっき追加した表Cのテストのとおりに logic.js と index.html を変更してください。test.html で全部○になるのが目標です。テストの実行は私がやります。

6リバース・エンジニアリング演習0:44〜0:51

ここまで、あなたはコードを 1 行も読んでいません。今あるコードが「何を決めているか」を Bob に説明させます。読むだけなので承認は出ません。

問い 1
test.html と harness.js と tests.js がどう組み合わさって ○× を出しているか、プログラミングを知らない人向けに 5 行以内で説明してください。
問い 2
logic.js を読んで、計算ルールを spec.md と同じ見出しの仕様書の形で書き出してください。そのうえで、spec.md・spec-change.md・spec-change-2.md のどこにも書いていないのに logic.js が決めていることを、別に箇条書きにしてください。

2 つ目の答えの「書いていないのに決めていること」を 1 つ選んで考えます。それは誰が決めましたか？ テストに書いてありますか？

動いているコードから仕様を取り戻す作業を「リバース・エンジニアリング」と呼びます。古いシステムの改修でいちばん難しいのは、この「書いていないのに決まっていること」です。

# シナリオ1:ブラウザだけで ToDo アプリを作る

Bob に ToDo アプリを作らせ、Bob にテストを書かせ、わざと壊したコードをテストで見つけて直させます。必要なのは **Bob** だけです(画面の確認は Bob の中のブラウザで行います。お使いの Web ブラウザでも確認できます)。Node.js は使いません。

## 全体の流れ

| ステップ | やること |
|---|---|
| 1〜3 | Bob に ToDo アプリを作らせ、ブラウザで動かして確認し、改善を頼む |
| 4〜5 | Bob にテスト画面 `tests.html` を作らせ、全部 PASS することを確認する |
| 6〜7 | 講師が示すバグ入りのファイルに差し替え、テストが FAIL することを確認する |
| 8〜9 | FAIL の内容を Bob に渡して直させ、テストと画面で完成を確認する |

## 事前準備

1. [共通準備](../common-setup.md)の 1〜4 を終わらせます(Bob のインストール、作業フォルダ、Agent モード)。
2. 画面の確認は Bob の中の「統合ブラウザー」で行います。別のブラウザで見たい場合は、Google Chrome または Microsoft Edge を推奨します(Safari や Firefox でも動作を確認しています)。

## ステップ1:Bob に ToDo アプリを作らせる

Bob のチャットに、次のプロンプトを**そのまま貼り付けて**送信します(自分の言葉に言い換えてもかまいませんが、関数の名前・引数・戻り値は変えないでください)。

```text
ToDo アプリを作ってください。タスクの追加、完了/未完了の切り替え、削除ができるものです。

作るファイルは、作業フォルダ直下の次の2つだけです。
- todo-logic.js:ロジック
- index.html:画面

import / export は使わないでください。index.html から、通常の <script src="todo-logic.js"></script> で読み込んでください。

■ データ
ToDo は { id: 数値, title: 文字列, done: 真偽値 } のオブジェクトです。ToDo の一覧は配列で表します。

■ 関数（API契約）
次の3つの関数を、この名前・引数・戻り値のとおりに作ってください。
- addTodo(list, title)：新しい配列を返す。title の前後の空白を除去して、配列の末尾に追加する。id は「現在の最大 id + 1」（空配列なら 1）、done は false。title が空文字または空白のみなら、追加せず、同じ内容の配列を返す。
- toggleTodo(list, id)：新しい配列を返す。id が一致する要素の done を反転する。一致する要素がなければ、内容は変わらない。
- removeTodo(list, id)：新しい配列を返す。id が一致する要素を取り除く。一致する要素がなければ、内容は変わらない。

■ 共通ルール
- 引数の配列は変更せず、新しい配列を返す。
- この3関数だけを置く。ほかの関数は置かない。
- 画面（DOM）や入出力には依存させない。

■ 画面仕様
- 上部に、タイトルを入力する欄と「追加」ボタンを置く。
- その下に、タスクの一覧を置く。各行に、完了を切り替えるチェックボックス、タイトル、「削除」ボタンを置く。
- 完了したタスクのタイトルは、取り消し線で表示する。
- 入力欄が空、または空白のみのときに「追加」を押しても、何も追加しない。
- 状態は index.html の中の変数で保持し、操作のたびに一覧を描画し直す。
- ロジックは todo-logic.js の addTodo / toggleTodo / removeTodo を呼ぶだけにする。
- id は数値のまま関数に渡す。HTML の属性（data-id など）から読み取る場合は文字列になるので、Number() で数値に変換してから toggleTodo / removeTodo に渡す。
- 見た目は、次の「デザイン指示」に従う。それ以外の見た目の作り込みは不要。

■ デザイン指示（IBM Design Language / Carbon 準拠）
- フォント：IBM Plex Sans JP の Light（300）と Medium（500）の2ウェイトだけを使う。<head> に次の2行を入れて Google Fonts から読み込む（外部ライブラリは使わない）。
  <link rel="preconnect" href="https://fonts.googleapis.com">
  <link rel="stylesheet" href="https://fonts.googleapis.com/css2?family=IBM+Plex+Sans+JP:wght@300;500&display=swap">
  font-family は "IBM Plex Sans JP", "Hiragino Sans", "Yu Gothic UI", "Meiryo", sans-serif とする。本文と見出しは Light（300）、ボタンの文字・ラベル・強調は Medium（500）にする。
- 配色：背景 #ffffff、入力欄や強調の面 #f4f4f4、文字 #161616、補助の文字 #525252、区切り線 #e0e0e0、アクセント（主ボタン）#0f62fe、削除や失敗は #da1e28、成功は #198038。
- 画面上部に、高さ48px・背景 #161616・白文字の帯（マストヘッダー）を置き、「IBM Bob ハンズオン」と表示する。
- 本文は幅の上限を設けて中央に寄せ、余白は8の倍数（8 / 16 / 24 / 32 / 48px）で揃える。角丸・影・グラデーションは使わない。
- ボタンと入力欄の高さは48px。主ボタン（追加）は背景 #0f62fe・白文字、ホバー時は #0353e9。入力欄は背景 #f4f4f4、下線だけ #8d8d8d。
- フォーカス時は、青（#0f62fe）の2pxの枠を出す。

コマンドは実行せず、ファイルの作成だけを行ってください。
```

長いプロンプトを貼り付けると、入力欄には本文ではなく「貼り付けテキスト #1 - ○○行」のような表示が出ます(行数は環境によって多少変わります)。これで正しく貼り付いているので、そのまま送信します。短いプロンプトは本文がそのまま表示されます。

Bob はまず `todo-logic.js`、次に `index.html` を作ろうとして、そのたびに「ファイル …を書き込み」の承認を求めてきます(共通準備で Edit の自動承認をオフにしているため)。左側に表示される差分(作られる中身)をざっと読んで、**一度だけ承認**を押します。ボタンの意味は次のとおりです。

| ボタン | 意味 |
|---|---|
| 一度だけ承認 | この1回の書き込みだけを許可する(この演習ではこれを使う) |
| 拒否 | 書き込みをやめさせる。理由をチャットで伝えると、Bob が作り直す |
| タスクのeditツールを承認 | このタスクの間は、以降のファイル書き込みを確認なしで許可する(この演習では使わない) |

Bob がファイルを作ったら、作業フォルダに `todo-logic.js` と `index.html` ができていることを確認します。

デザインの指示(フォントと配色)も入っているので、`index.html` は IBM のデザインに近い見た目になります。フォントは Google Fonts から読み込むため、オンラインでないと OS の日本語フォントで表示されます(動作には影響しません)。

> Bob がコマンドを実行しようとして承認を求めてきたら、**拒否**して、「コマンドは実行せず、ファイルの作成だけをしてください」と伝えてください。

## ステップ2:ブラウザで動かして確認する

作業フォルダの `index.html` を、Bob の中のブラウザで開きます。

1. Bob の左側のエクスプローラーで `index.html` を右クリックします。
2. **統合ブラウザーで開く** を選びます。Bob の中にタブが開き、ToDo 画面が表示されます。

> 統合ブラウザーの再読み込みは、タブの上部(アドレスバーの左、← → の右隣)にある小さな円形の矢印の **再読み込みボタン** を押します。`Ctrl + R` などのキー操作は効きません。押したあとに表示が変わらないときは、隣のボタンを押している可能性があるので、もう一度押してください。

お使いの Web ブラウザで開きたい場合は、次の方法もあります。

| OS | 操作 |
|---|---|
| Windows | Bob のエクスプローラーで `index.html` を右クリック → **エクスプローラーで表示する** → `index.html` をダブルクリックする。別のアプリで開く場合は、右クリック → プログラムから開く → お使いのブラウザ(Chrome、Edge、Firefox など) |
| macOS | Bob のエクスプローラーで `index.html` を右クリック → **Finder で表示** → `index.html` を右クリック → このアプリケーションで開く → お使いのブラウザ(Chrome、Safari、Edge、Firefox など) |

次の項目を、実際に操作して確認します。

- [ ] 入力欄にタイトルを入れて「追加」を押すと、一覧に表示される
- [ ] チェックボックスをオンにすると、取り消し線が付く。オフにすると戻る
- [ ] 「削除」を押すと、その行だけが消える
- [ ] 入力欄が空のまま、またはスペースだけで「追加」を押しても、何も追加されない

> 画面が真っ白、またはボタンが反応しない場合は、開発者ツールのコンソールにエラーが出ていないか確認します。開発者ツールは、Windows は `F12`、macOS は `Command + Option + I` で開きます。エラーの文章をそのまま Bob に貼り付けて、直してもらいましょう。

> このアプリは、タスクをブラウザのメモリにだけ持ちます。ページを再読み込みすると、追加したタスクは消えます。これは仕様で、不具合ではありません。

## ステップ3:改善を頼む

> **パターン1(1 時間コース)の人は、このステップ3を飛ばしてステップ4へ進みます。** 時間が余ったら最後に試してください。

動いたら、Bob に改善を頼みます。次の中から選んでください(複数でもかまいません)。例Cを入れておくと、あとのステップで動作を確認するとき、タスクを手で入力しなくて済みます。

**例A:Enter キーで追加**

> Bob は、頼まなくても最初から Enter キーでの追加を入れていることがあります。その場合は「すでに対応しています」のような返事になるので、例B か例C を選んでください。Enter の処理はすでにあるが、日本語入力の変換を確定する Enter で追加されないようにする対策(`isComposing` の条件)だけを加える差分を出すこともあります(2026-10-26 の macOS 実機)。その場合は、差分を読んで **一度だけ承認** を押せば例A は完了です。

```text
index.html を変更して、入力欄で Enter キーを押したときも、「追加」ボタンと同じように追加されるようにしてください。見た目(デザイン)は変えないでください。todo-logic.js は変更しないでください。コマンドは実行せず、ファイルの編集だけを行ってください。
```

**例B:未完了の件数を表示**

```text
index.html を変更して、一覧の上に「未完了:N件」という表示を出してください。N は done が false のタスクの数です。既存のデザインに合わせてください。todo-logic.js は変更しないでください。コマンドは実行せず、ファイルの編集だけを行ってください。
```

**例C:サンプルを読み込む**

```text
index.html を変更して、「サンプルを読み込む」ボタンを追加してください。押すと、いまの一覧を次の3件で置き換えて、描画し直します。

[
  { id: 1, title: '牛乳を買う', done: false },
  { id: 2, title: 'レポートを書く', done: true },
  { id: 3, title: '電話をかける', done: false }
]

このデータは index.html の中に書いてください。読み込んだあとに追加すると、id は 4 になります(todo-logic.js の addTodo の仕様どおり)。見た目(デザイン)は変えず、既存のデザインに合わせてください。todo-logic.js は変更しないでください。コマンドは実行せず、ファイルの編集だけを行ってください。
```

> 変更が複数回に分かれて、承認を 2 回以上求められることがあります。そのたびに差分を読んで、**一度だけ承認** を押してください。

変更されたら、`index.html` を開いているタブを再読み込みして(統合ブラウザーは再読み込みボタン。Web ブラウザは Windows が `Ctrl + R`、macOS が `Command + R`)、動作を確認します。例Cを入れた場合は、「サンプルを読み込む」を押すと3件(1件は完了済み)が表示されることも確認します。

> `todo-logic.js` は変えないでください。あとで、講師が示すファイルで `todo-logic.js` を差し替えます。ここに独自の関数が増えていると、差し替えたあとに `index.html` が動かなくなります。

## ステップ4:Bob にテストを書かせる

テスト用の画面 `tests.html` を、Bob に作らせます。次のプロンプトを貼り付けて送信します。

```text
todo-logic.js の3つの関数（addTodo / toggleTodo / removeTodo）をテストする画面 tests.html を、作業フォルダ直下に作ってください。

条件:
- import / export は使わない。tests.html から、通常の <script src="todo-logic.js"></script> で todo-logic.js を読み込む。
- テストフレームワークは使わず、自作の test(name, fn) と assertEqual(actual, expected) を tests.html の中に書く。
- assertEqual は、配列やオブジェクトを「内容」で比較できるようにする（=== だけで比較しない）。
- 結果は画面に一覧で表示する。一番上に「N件中M件 PASS」と表示する。
- FAIL のときは、テスト名、期待値、実際の値を表示する。期待値と実際の値は、JSON.stringify で1行の JSON にして表示する（改行や字下げで縦に長くしない）。
- todo-logic.js は変更しない。
- コマンドは実行せず、ファイルの作成だけを行う。

■ デザイン指示（IBM Design Language / Carbon 準拠）
- フォント：IBM Plex Sans JP の Light（300）と Medium（500）の2ウェイトだけを使う。<head> に次の2行を入れて Google Fonts から読み込む（外部ライブラリは使わない）。
  <link rel="preconnect" href="https://fonts.googleapis.com">
  <link rel="stylesheet" href="https://fonts.googleapis.com/css2?family=IBM+Plex+Sans+JP:wght@300;500&display=swap">
  font-family は "IBM Plex Sans JP", "Hiragino Sans", "Yu Gothic UI", "Meiryo", sans-serif とする。本文と見出しは Light（300）、ラベル・強調は Medium（500）にする。
- 配色：背景 #ffffff、強調の面 #f4f4f4、文字 #161616、補助の文字 #525252、区切り線 #e0e0e0、失敗は #da1e28、成功は #198038。
- 画面上部に、高さ48px・背景 #161616・白文字の帯（マストヘッダー）を置き、「IBM Bob ハンズオン」と表示する。
- 本文は幅の上限を設けて中央に寄せ、余白は8の倍数（8 / 16 / 24 / 32 / 48px）で揃える。角丸・影・グラデーションは使わない。

■ テスト画面のデザイン指示
- 一番上に、結果のまとめ（「N件中M件 PASS」）を、背景 #f4f4f4 の帯で出す。帯の左端に太さ4pxの線を付け、すべて PASS なら #198038、1件でも FAIL があれば #da1e28 にする。
- 各テストは1行ずつ並べる。行の左端に太さ4pxの線を付け、PASS は #198038（背景 #defbe6）、FAIL は #da1e28（背景 #fff1f1）にする。
- 行頭の「PASS:」「FAIL:」の文字は Medium（500）にし、PASS は #198038、FAIL は #da1e28 の文字色にする（色だけに頼らず、文字でも区別できるようにする）。
- FAIL の行には、期待値と実際の値を、白背景・細い枠線のブロックで、等幅フォントで1行ずつ表示する。

次の T1〜T7 をすべて網羅してください。テスト名は「T番号: 日本語の説明」の形式にしてください（例：「T1: 追加すると件数が1増える」）。1つの T番号に複数のテストを作ってもよいですが、すべての名前をその T番号で始めてください。

- T1：addTodo で追加すると件数が1増え、追加された要素の title は渡した文字列、done は false になる。id は、空配列に追加したら 1、既存の要素があれば既存の最大 id + 1 になる。
- T2：addTodo に空文字（''）や空白のみ（'   '）のタイトルを渡しても追加されず、配列の内容が変わらない。
- T3：addTodo に前後に空白があるタイトル（例：'  牛乳  '）を渡すと、空白が除去されて追加される。
- T4：toggleTodo で、指定した id の done が true になる。存在しない id を渡すと、内容が変わらない。
- T5：toggleTodo を同じ id で2回呼ぶと、done が元に戻る。
- T6：removeTodo で、指定した id の要素だけが消え、ほかの要素は残る。存在しない id を渡すと、何も消えない。
- T7：addTodo / toggleTodo / removeTodo のどれも、渡した元の配列を変更しない。T7 は「元の配列が変わらないこと」だけを確認し、戻り値の内容は確認しない。
```

## ステップ5:テストを実行して全部 PASS を確認する

作業フォルダの `tests.html` を、ステップ2と同じ方法(右クリック → **統合ブラウザーで開く**)で開きます。

- 一番上に「N件中N件 PASS」(すべて PASS)と表示されることを確認します。テストの件数(N)は、Bob が作ったテストによって変わります(13件や14件など)。Bob がチャットで報告する件数と画面の件数が 1 件ほどずれることがありますが、画面の件数が正です。
- 上部の帯の左端が緑(すべて PASS のとき)になり、各行の左端も緑になっていることを確認します。
- 画面にテスト名が `T1:` 〜 `T7:` で並んでいることも確認します。T1〜T7 のどれかが見当たらない場合は、Bob に「T○ のテストが足りません。追加してください」と頼みます。

## ステップ6:バグ入りのファイルに差し替える

ここから先は、**講師の指示を待ちます**。

講師の合図が出たら、[共通準備の 5](../common-setup.md) の手順で、`bobathon-todo/scenario1-browser/bug/todo-logic.js` を作業フォルダの `todo-logic.js` に上書きコピーします。

バックアップは不要です(元の正しいファイルは、講師が予備を持っています)。

## ステップ7:テストが FAIL することを確認する

`tests.html` を**再読み込み**します。

| 開き方 | 操作 |
|---|---|
| Bob の統合ブラウザー | タブ上部(← → の右隣)の小さな円形の矢印 **再読み込みボタン** を押す(キー操作は効きません。結果が変わらなければもう一度押す) |
| Web ブラウザ(Windows) | `Ctrl + Shift + R`(強制再読み込み) |
| Web ブラウザ(macOS) | `Command + Shift + R`(強制再読み込み) |

名前が `T6:` で始まるテストが FAIL(赤)になることを確認します。結果が変わらないときは、ブラウザが古いファイルを使っている(キャッシュ)可能性があるので、もう一度再読み込みしてください。

> 期待値と実際の値は、Bob が作ったテストの書き方によって、配列の JSON ではなく「2」「1」のような件数だけのこともあります。どちらでも、そのまま次のステップで Bob に渡せます。

## ステップ8:FAIL の内容を Bob に渡して直させる

FAIL したテストの名前、期待値、実際の値を、画面からコピーして Bob に貼り付けます(FAIL の行から実際の値の行までをドラッグして選び、`Ctrl + C`(macOS は `Command + C`)でコピーします)。統合ブラウザーの中でうまくコピーできないときは、無理にコピーせず、画面を見ながら「テスト名・期待値・実際の値」を手で入力しても構いません(件数や短い文字列なので、手入力でも Bob は原因にたどり着けます)。たとえば次のように頼みます。

```text
tests.html で次のテストが FAIL しました。原因を調べて、todo-logic.js を修正してください。tests.html は変更しないでください。コマンドは実行せず、ファイルの編集だけを行ってください。

（ここに、画面の FAIL 表示をそのまま貼り付ける）
```

Bob は `todo-logic.js` を読み、`removeTodo` の条件を直す差分(1行だけ変わります)を示して承認を求めてきます。修正の内容を読んで、納得できてから**一度だけ承認**を押してください。

## つまずきやすい点

| 症状 | 対処 |
|---|---|
| Bob がコマンドを実行しようとする | 拒否して、「コマンドは実行せず、ファイルの作成だけをしてください」と頼む |
| `import` / `export` が入っていて画面が動かない | Bob に「import / export を使わず、通常の script で読み込む形に直してください」と頼む |
| 画面が真っ白 | 開発者ツール(Windows は `F12`、macOS は `Command + Option + I`)のコンソールのエラーを、Bob に貼り付ける |
| チェックや削除が効かない | Bob に「data-id から読んだ id を Number() で数値にしてから関数に渡してください」と頼む |
| 差し替えたのに結果が変わらない | ファイル名が `todo-logic.js` か確認し、再読み込みする(統合ブラウザーは再読み込みボタン。キー操作では再読み込みされない) |
| 生成したファイルの関数名が違う | Bob に、上のプロンプトの「関数（API契約）」の部分をもう一度示して、名前を合わせるよう頼む。直らないときは講師に声をかける(講師が正しい `todo-logic.js` を示します) |

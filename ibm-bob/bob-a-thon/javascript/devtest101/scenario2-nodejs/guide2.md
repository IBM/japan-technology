# シナリオ2:Node.js で ToDo アプリを作る

Bob に ToDo アプリ(ロジック + 対話型のコマンドライン)を作らせ、Bob にテストを書かせて**実行**させ、わざと壊したコードをテストで見つけて直させます。必要なのは **Bob** と **Node.js** です。

## 全体の流れ

| ステップ | やること |
|---|---|
| 1〜3 | Bob にロジック `todo.js` とコマンドライン `cli.js` を作らせ、自分のターミナルで動かして確認する |
| 4〜6 | Bob にテスト `todo.test.js` を作らせ、Bob にテストを実行させて全部 PASS を確認する |
| 7〜8 | 講師が示すバグ入りのファイルに差し替え、テストが失敗することを確認する |
| 9〜10 | 失敗の内容を Bob に渡して直させ、テストとコマンドラインで完成を確認する |

### 2. バージョン要件

Node.js は、**脆弱性が修正された版**が必要です。古い版や、サポートが終わった版は使えません。

| あなたの Node.js | 合格の条件(2026-10-23 時点) |
|---|---|
| 22 系 | 22.23.4 以上 |
| 24 系 | 24.22.1 以上 |
| 26 系 | 26.12.1 以上 |
| 20 以下、23、25 | 不合格(サポートが終了した版。更新が必要) |
| 27 以上 | 講師に相談する |

- 理由:2026-10-21 のセキュリティリリースで、重大度が high のものを含む脆弱性が修正されました。詳しくは [Node.js の公式ブログ](https://nodejs.org/en/blog/vulnerability/october-2026-security-releases)を見てください。
- 新しく入れる場合は、公式の [Download ページ](https://nodejs.org/en/download)で、**LTS** と書かれた最新の版を選びます。
- 最低ラインは更新されることがあります。最新の情報は[公式の脆弱性情報の一覧](https://nodejs.org/en/blog/vulnerability)で確認でき、講師が当日に再確認します。

|---|---|

| 表示 | 判断 | 次にやること |

### Node.js のインストールと更新

新しく入れる場合も、更新する場合も、同じ手順です。

1. [Node.js の Download ページ](https://nodejs.org/en/download)を開き、**LTS** の最新版のインストーラーをダウンロードします。
2. インストーラーを実行し、画面の案内に従って進めます。
3. **ターミナルを開き直して**、`node -v` を実行します。表示された版が、上の表の合格の条件を満たしていることを確認します。

> `node -v` が認識されない、または更新前の版が表示される場合は、ターミナルと Bob を再起動してから、もう一度試してください。

Homebrew、nvm、winget など、公式インストーラー以外の方法で入れた人は、**入れた方法に対応する更新方法**で更新してください。更新後に、必ず `node -v` で合格の条件を満たしていることを確認します。

| 入れた方法 | 対象 OS | 更新の操作 |
|---|---|---|
| Homebrew | macOS | `brew update` を実行し、続けて `brew upgrade node@24` を実行する(LTS の 24 系を入れている場合) |
| nvm | macOS、Linux、WSL | `nvm install --lts` を実行し、続けて `nvm use --lts` を実行する。新しいターミナルでも使うには `nvm alias default 'lts/*'` も実行する |
| winget | Windows | `winget upgrade --id OpenJS.NodeJS.LTS -e` を実行する(未インストールなら `winget install --id OpenJS.NodeJS.LTS -e`) |

注意点です。

- **Homebrew:** `brew upgrade node`(`node@24` ではない)は、LTS ではなく最新の Current 版(26 系)に上がります。LTS を使いたい場合は `node@24` を使います。`node@24` は PATH に自動では出ないため、`node -v` が更新前の版のままなら、`brew link --overwrite node@24` を試すか、講師に声をかけてください。
- **nvm:** 公式の nvm は Windows のネイティブ環境(PowerShell)では使えません。Windows では winget か、公式インストーラーを使います。
- **winget:** `OpenJS.NodeJS` は Current 版のパッケージです。LTS を入れるときは `OpenJS.NodeJS.LTS` を指定します。更新後は、ターミナルを開き直します。
- どの方法でも、更新後に `node -v` が更新前の版のままなら、ターミナルと Bob を再起動します。それでも直らなければ、講師に声をかけてください。

根拠は、各公式ドキュメントです([Homebrew](https://docs.brew.sh/Manpage)、[nvm](https://github.com/nvm-sh/nvm)、[winget upgrade](https://learn.microsoft.com/en-us/windows/package-manager/winget/upgrade))。

## ステップ1:Bob にロジック(`todo.js`)を作らせる

Bob のチャットに、次のプロンプトを**そのまま貼り付けて**送信します(自分の言葉に言い換えてもかまいませんが、関数の名前・引数・戻り値は変えないでください)。

```text
ToDo アプリのロジックを作ってください。

作るファイルは、作業フォルダ直下の todo.js だけです。CommonJS で書き、末尾で module.exports = { addTodo, toggleTodo, removeTodo }; と書き出してください。import / export は使わないでください。外部パッケージは使わず、package.json も作らないでください。

■ データ
ToDo は { id: 数値, title: 文字列, done: 真偽値 } のオブジェクトです。ToDo の一覧は配列で表します。

■ 関数（API契約）
次の3つの関数を、この名前・引数・戻り値のとおりに作ってください。
- addTodo(list, title)：新しい配列を返す。title の前後の空白を除去して、配列の末尾に追加する。id は「現在の最大 id + 1」（空配列なら 1）、done は false。title が空文字または空白のみなら、追加せず、同じ内容の配列を返す。
- toggleTodo(list, id)：新しい配列を返す。id が一致する要素の done を反転する。一致する要素がなければ、内容は変わらない。
- removeTodo(list, id)：新しい配列を返す。id が一致する要素を取り除く。一致する要素がなければ、内容は変わらない。

■ 共通ルール
- 引数の配列は変更せず、新しい配列を返す。
- この3関数だけを置く。ほかの関数は置かない。
- 画面（DOM）や入出力には依存させない。

コマンドは実行せず、ファイルの作成だけを行ってください。
```

作業フォルダに `todo.js` ができていることを確認します。

> Bob がコマンドを実行しようとして承認を求めてきたら、**拒否**して、「コマンドは実行せず、ファイルの作成だけをしてください」と伝えてください。

## ステップ2:Bob にコマンドライン(`cli.js`)を作らせる

次のプロンプトを貼り付けて送信します。

```text
todo.js を使う、対話型のコマンドライン cli.js を、作業フォルダ直下に作ってください。

条件:
- CommonJS で書く。todo.js は require('./todo') で読み込み、変更しない。
- 標準入力の読み取りには Node.js 標準の node:readline を使う。外部パッケージは使わない。package.json は作らない。
- コマンドは実行せず、ファイルの作成だけを行う。

■ CLI仕様
- 起動すると「> 」というプロンプトを出し、1行ずつコマンドを受け付ける。空行は無視する。
- 標準入力が終了（EOF）した場合は、exit と同じく正常終了する。
- ロジックは todo.js の addTodo / toggleTodo / removeTodo を使い、データは cli.js の変数（メモリ）に持つ。
- 入力の解釈：コマンド名は小文字のみ（大文字は「不明なコマンド」として扱う）。コマンド名と引数は、最初の空白で分ける。add のタイトルは、最初の空白より後ろすべて。id は、半角数字だけの文字列（正規表現 ^[0-9]+$）のときだけ有効とし、Number() で数値にして関数へ渡す。done / remove で id が省略された場合も、「id が見つかりません: 」（入力は空）と同じ扱いにする。
- 出力：プロンプト「> 」は改行なしで出す。応答は1行ごとに改行する。

| コマンド | 動作 | 成功時の表示 | エラー時の表示 |
|---|---|---|---|
| add <タイトル> | addTodo で追加 | 追加しました: <id>: <title> | タイトルが空または空白のみ：タイトルを入力してください |
| list | 一覧を表示 | 1行1件で「[ ] 1: 牛乳を買う」「[x] 2: レポート」（[x] は完了） | 0件：(タスクはありません) |
| done <id> | toggleTodo で完了 / 未完了を切り替え | 切り替えました: <id> | id が整数でない、または存在しない：id が見つかりません: <入力> |
| remove <id> | removeTodo で削除 | 削除しました: <id> | 同上 |
| exit | 終了する | なし | |
| 上記以外 | | | 不明なコマンドです: <入力> |

- done は、完了にも未完了にも戻せる（toggleTodo の挙動に合わせる）。
- 存在しない id かどうかは cli.js 側で判定してメッセージを出す（toggleTodo / removeTodo は、一致がなければ何も変えないため）。

■ 入出力の例
入力（1行ずつ）：
add 牛乳を買う
add   レポート
list
done 2
list
done 9
remove 1
list
remove abc
foo
add
exit

出力（プロンプト「> 」を除いた応答）：
追加しました: 1: 牛乳を買う
追加しました: 2: レポート
[ ] 1: 牛乳を買う
[ ] 2: レポート
切り替えました: 2
[ ] 1: 牛乳を買う
[x] 2: レポート
id が見つかりません: 9
削除しました: 1
[x] 2: レポート
id が見つかりません: abc
不明なコマンドです: foo
タイトルを入力してください
```

2. 次を実行します。


3. `> ` が表示されたら、次のように入力してみます。

   ```text
   add 牛乳を買う
   add レポート
   list
   done 2
   list
   remove 1
   list
   exit
   ```

次の項目を確認します。

## ステップ4:Bob にテストを書かせる

次のプロンプトを貼り付けて送信します。

```text
todo.js の3つの関数（addTodo / toggleTodo / removeTodo）をテストする todo.test.js を、作業フォルダ直下に作ってください。

条件:
- CommonJS で書く。Node.js 標準の node:test と node:assert だけを使う。外部パッケージは使わない。
- todo.js は変更しない。
- コマンドは実行せず、ファイルの作成だけを行う。（実行は次のステップで頼みます。）

次の T1〜T7 をすべて網羅してください。テスト名は「T番号: 日本語の説明」の形式にしてください（例：「T1: 追加すると件数が1増える」）。1つの T番号に複数のテストを作ってもよいですが、すべての名前をその T番号で始めてください。

- T1：addTodo で追加すると件数が1増え、追加された要素の title は渡した文字列、done は false になる。id は、空配列に追加したら 1、既存の要素があれば既存の最大 id + 1 になる。
- T2：addTodo に空文字（''）や空白のみ（'   '）のタイトルを渡しても追加されず、配列の内容が変わらない。
- T3：addTodo に前後に空白があるタイトル（例：'  牛乳  '）を渡すと、空白が除去されて追加される。
- T4：toggleTodo で、指定した id の done が true になる。存在しない id を渡すと、内容が変わらない。
- T5：toggleTodo を同じ id で2回呼ぶと、done が元に戻る。
- T6：removeTodo で、指定した id の要素だけが消え、ほかの要素は残る。存在しない id を渡すと、何も消えない。
- T7：addTodo / toggleTodo / removeTodo のどれも、渡した元の配列を変更しない。T7 は「元の配列が変わらないこと」だけを確認し、戻り値の内容は確認しない。
```

作業フォルダに `todo.test.js` ができていることを確認します。

## ステップ5:Bob にテストを実行させる

ここでは、Bob に**コマンドを実行してもらいます**。次のプロンプトを送信します。

```text
次のコマンドを実行して、結果を教えてください。

node --test --test-reporter=spec
```

Bob がコマンドの実行の確認を求めてきます。

1. 表示されたダイアログで、**実行されるコマンドの内容を読みます**。`node --test --test-reporter=spec` になっていることを確認します。
2. 提案されたコマンドは、実行前に**編集**できます(Bob の公式ドキュメントでも説明されています)。この演習では、編集せずにそのまま使います。
3. 内容に問題がなければ**承認**します。

> コマンドの自動承認(Execute)は、この演習では使いません。毎回、内容を読んでから承認してください。

## ステップ6:全部 PASS を確認する

出力は、次のようになります(数字や時間は多少変わります)。

```text
✔ T1: 空配列に追加すると件数が1増え、id は 1、done は false になる (0.7ms)
✔ T1: 既存の要素があれば id は最大 id + 1 になる (0.07ms)
…(T2〜T7 も同じ形式で並ぶ)…
✔ T7: removeTodo は元の配列を変更しない (0.04ms)
ℹ tests 13
ℹ suites 0
ℹ pass 13
ℹ fail 0
ℹ cancelled 0
ℹ skipped 0
ℹ todo 0
ℹ duration_ms 56.7
```

- 各行の `✔` はそのテストが成功したこと、`✖` は失敗したことを表します。
- 終わりの `pass` が成功した数、`fail` が失敗した数です。`fail 0` なら全部 PASS です。
- テスト名が `T1:` 〜 `T7:` で並んでいることを確認します。足りない T番号があれば、Bob に「T○ のテストが足りません。追加してください」と頼みます。
- テストの数(`tests`)は、Bob が作ったテストによって 13 とは限りません。

## ステップ8:テストが失敗することを確認する

ステップ5と同じ依頼を、Bob にもう一度します。

```text
次のコマンドを実行して、結果を教えてください。

```

名前が `T6:` で始まるテストが `✖` になり、終わりの `fail` が 1 以上になることを確認します。失敗したテストの下には、期待した値(`expected`)と実際の値(`actual`)が表示されます。

テストが失敗すると、コマンドの終了コードは 1 になります(成功なら 0 です)。

## ステップ9:失敗の内容を Bob に渡して直させる

Bob は、自分が実行したテストの結果を読めます。次のように頼みます。

```text

```

Bob は `removeTodo` の条件を直すはずです。修正の内容を読んで、納得できてから承認してください。

## ステップ10:完成の確認

- [ ] Bob が再実行したテストが、`fail 0`(全部 PASS)に戻った

## つまずきやすい点

| 症状 | 対処 |
|---|---|
| `node` が認識されない | ターミナルと Bob を再起動する。それでも直らなければ、Node.js のインストールをやり直す |
| Bob が `import` / `export` を使っている | Bob に「CommonJS(require / module.exports)で書き直してください」と頼む |
| `node cli.js` が `Cannot find module './todo'` と表示する | `todo.js` が `cli.js` と同じフォルダにあるか、ターミナルが作業フォルダにいるか確認する |
| `node --test --test-reporter=spec` が何も実行しない | `todo.test.js` が作業フォルダ直下にあるか確認する |
| 差し替えたのに結果が変わらない | ファイル名が `todo.js` か確認する。作業フォルダ以外に保存していないか確認する |
| 生成したファイルの関数名が違う | Bob に、ステップ1のプロンプトの「関数（API契約）」の部分をもう一度示して、名前を合わせるよう頼む。直らないときは講師に声をかける(講師が正しい `todo.js` を示します) |

# パターン1:1 時間コース(シナリオ1 → E2E テスト入門)

Bob に ToDo アプリを作らせ、ユニットテスト(シナリオ1)と E2E テスト(シナリオ2)の両方を 1 時間で体験します。インストールとダウンロードは[事前課題](pre-assignment.md)で済ませておきます。

## 当日までに

[事前課題](pre-assignment.md)の 1〜5 を済ませます(20〜30 分)。当日は「できている」前提で始めます。

## 当日の進め方(60 分)

| 時間 | 内容 | 手順書 | 受講者の操作 |
|---|---|---|---|
| 0:00〜0:05 | 事前課題の確認(`node -v`、`agent-browser --version` が 0.39 以上、`agent-browser open https://example.com; agent-browser get title; agent-browser close` が通る、Bob設定 > スキル) | [事前課題](pre-assignment.md) | 確認のみ |
| 0:05〜0:35 | シナリオ1:ブラウザだけで ToDo アプリを作る。**ステップ3(改善の依頼)は省略** | [guide1](scenario1-browser/guide1.md) | ステップ1→2→4→5→6→7→8→9 |
| 0:35〜0:50 | シナリオ2:E2E テスト入門。ステップ5(全部 PASS と画像の確認)まで。終わった人はステップ8 の後片付け | [guide-e2e](e2e/guide-e2e.md) | ステップ1〜5、8 |

## 講師の準備

- 事前課題の 4(約 200 MB のダウンロード)が会社ネットワークで止まる受講者がいる可能性。当日はペアでの進行を案内できるようにしておく。冒頭 5 分で `agent-browser --version`(0.39 以上)、`agent-browser open https://example.com; agent-browser get title; agent-browser close` が通ること、Bob設定 > スキル の「agent-browser(グローバル)」を全員で確認する(グローバル登録は Bob を起動し直すまで一覧に出ない)。版の表示だけでは古い版(0.28 など)を見分けられず、古い版では E2E のステップ3 で `open` が失敗する(実機で確認)。
- 講師自身の PC は、当日前に Bob設定 > チャット を確認する:**編集(Edit)の自動承認がオフ**になっているか、実行 > 許可されたコマンド に前回の `agent-browser` が**残っていないか**(残っていると、デモの承認の流れが受講者と変わる)。
- IBM 社員が使う **Insiders 版(2.3.0-insider)** では、チャット入力欄の左下にモード名のボタン(Agent ▾)が表示されず、＋ と 権限 だけになる(受講者の GA 版とは見た目が違う。[共通準備の 4](common-setup.md) に注記あり)。受講者の画面を説明するときは GA 版の表示で説明する。
- デモ用に、自分の PC で E2E がステップ5まで通った状態を作っておく(差し替え → FAIL → 修正 → PASS は実機で約 4 分、承認 1 回)。デモでは `bug-step4.png` と `fixed-step4.png` を Bob 内で開き、「同じバグをユニットテストは関数の戻り値で、E2E は画面の症状で見つける」ことを画像で見せる。
- 受講者に先に伝えておくこと(実機確認で見えた Bob の揺れ): (1) ステップ4 の承認は「許可リストの ✓ が緑になったのを確かめてから、タスクに対して承認」。(2) Bob が server.js を一度書いてから CommonJS に書き直し、承認が 2 回になることがある。(3) Bob が E2E の途中で手順を間違えても自分でやり直し、報告に書く。そのまま待ってよい。(4) 報告の PASS と画像が合っているかを自分の目で見る。
- E2E の指示文は手順書のものを**そのまま**貼ること(`'@e3'` のクォート規則と「reload は開始前に 1 回だけ」の行を省くと、失敗や途中の reload が起きる)。
- バグ入りファイルは `scenario1-browser/bug/todo-logic.js`(シナリオ1と共通)。

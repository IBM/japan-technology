# E2E テスト入門:Node.js でホストして、Bob に画面を操作させる

シナリオ1で作った ToDo アプリを **Node.js の Web サーバーでホスト**し、ブラウザ自動操作ツール **agent-browser** を Bob のスキルとして使って、Bob に**画面を操作するテスト(E2E テスト)**を実行させます。

この手順書は、2 つのパターンで使います。

| パターン | 位置づけ | インストール | バグ差し替え(ステップ7〜8) |
|---|---|---|---|
| パターン1 | シナリオ2(全員) | [事前課題](../pre-assignment.md)で済ませてある | 講師のデモを見る |
| パターン2 | オプション課題(任意) | この場で行う([事前課題](../pre-assignment.md)の 4〜5) | 各自で行う |

必要なもの:**Bob**、**Node.js**(シナリオ2の版の条件)、シナリオ1で作った `index.html` と `todo-logic.js`、agent-browser とそのスキル。

## 全体の流れ

| ステップ | やること |
|---|---|
| 1〜2 | Bob に Web サーバー `server.js` を作らせ、自分のターミナルで起動して画面を確認する |
| 3〜5 | 自分で agent-browser のブラウザを開き、Bob に E2E テストを実行させて全部 PASS を確認する |
| 6〜7 | バグ入りのファイルに差し替え、E2E テストが失敗することを確認し、Bob に直させる(パターン1は講師デモ) |
| 8 | 後片付け |

## 事前準備

1. **パターン1:** [事前課題](../pre-assignment.md)の 1〜5 が済んでいることを確認します。`agent-browser --version` が版を表示し、Bob設定 > スキル に `agent-browser`(スコープ: グローバル)があれば OK です。
2. **パターン2:** [共通準備](../common-setup.md)の 1〜4 と、[シナリオ2(Node.js コマンドライン版)の事前準備 2〜3](../scenario2-nodejs/guide2.md)(Node.js の版)を終わらせたうえで、[事前課題](../pre-assignment.md)の **4〜5**(agent-browser の導入とスキル登録)を、いまここで行います(10〜15 分)。
3. シナリオ1の作業フォルダ(`index.html` と `todo-logic.js` がある状態)を Bob で開きます。ファイルがない人は講師に声をかけてください(講師が正しい 2 ファイルを示します)。
4. Bob の中でターミナルを開きます(メニューバーの **[ターミナル] > [新しいターミナル]**。ウィンドウが狭いときは `...` の中にあります)。この手順ではターミナルを **2 本**使うので、1 本目を「ターミナル A」、あとで開く 2 本目を「ターミナル B」と呼びます。

## ステップ1:Bob に Web サーバーを作らせる

Bob のチャットに、次のプロンプトを**そのまま貼り付けて**送信します。

```text
作業フォルダの index.html と todo-logic.js を、Node.js でホストする簡単な Web サーバーを作ってください。

- 作るファイルは server.js の 1 つだけ。npm パッケージは使わず、Node.js 標準の node:http / node:fs / node:path だけを使う
- ポートは 3000。http://localhost:3000/ で index.html を、/todo-logic.js で todo-logic.js を返す
- 拡張子に応じて Content-Type（html, js, css）を付ける。存在しないパスは 404
- 作業フォルダの外のファイルは返さない
- 起動したら「http://localhost:3000 で起動しました」と表示する
- index.html と todo-logic.js は変更しない
- サーバーの起動は私が自分のターミナルで行うので、コマンドは実行しないでください
```

Bob が `server.js` の書き込みの承認を求めてきます。差分をざっと読んで(`require('node:http')` があり、ポートが 3000 であることを確認)、**一度だけ承認** を押します。

> Bob が一度書いたあとで「`import` 構文は package.json がないと動かないので CommonJS に書き直します」と、もう一度書き込みの承認を求めることがあります。内容を読んで、もう一度 **一度だけ承認** を押してください。すでにステップ2でサーバーを起動していたら、ターミナル A で `Ctrl + C` を押してから起動し直します。

## ステップ2:サーバーを起動して画面を確認する

1. ターミナル A で次を実行します。`http://localhost:3000 で起動しました` と出たら、**このターミナルはそのままにします**(止めるとサーバーも止まります)。

```text
node server.js
```

2. ターミナルパネルの **＋** を押して、2 本目のターミナル(ターミナル B)を開きます。以降のコマンドはターミナル B で実行します。
3. `Ctrl + Shift + P`(macOS は `Command + Shift + P`)でコマンドパレットを開き、`Open Integrated Browser` と入力して **ブラウザー: 統合ブラウザーを開く** を選びます(日本語で「統合ブラウザー」と入力しても見つかります)。アドレス欄に `http://localhost:3000/` を入力して Enter を押すと、シナリオ1の ToDo 画面が表示されます(統合ブラウザーの使い方は[共通準備の 6](../common-setup.md)にもあります)。

シナリオ1では `file://` でファイルを直接開きましたが、今回は **Node.js のサーバーが配っている** `http://` の画面です。

## ステップ3:自分でブラウザを開き、画面の部品を見る

ターミナル B で、次を実行します。

```text
agent-browser open http://localhost:3000/
```

```text
agent-browser snapshot -i
```

2 つ目の出力は、次のようになります(番号は変わります)。

```text
- textbox "タスクタイトル" [ref=e3]
- button "追加" [ref=e1]
- button "サンプルを読み込む" [ref=e2]
```

これが **E2E テストの入り口**です。agent-browser は画面を「部品の一覧」として読み取り、`@e3` のような番号で部品を指定して入力やクリックをします。Bob はこの一覧を見ながら、人と同じ手順で画面を操作します。

> ブラウザを開く(`open`)のは、必ず自分のターミナルで行います。Bob に `open` をさせると、裏で動き続けるプロセスを Bob が待ち続けて、作業が止まってしまいます(ステップ4のプロンプトで禁止しています)。

## ステップ4:Bob に E2E テストを実行させる

### 最初の承認で、まとめて許可する

Bob は `agent-browser` のコマンドを何度も実行します(1 回のテストで 5〜12 回)。毎回「一度だけ承認」を押してもよいのですが、ここでは **最初の承認のときに 2 つの操作**をして、このタスクの間はまとめて許可します。

1. 下のプロンプトを送ると、Bob が最初のコマンド(`agent-browser skills get core` または `agent-browser reload; ...`)の承認を求めてきます。コマンドの内容を読みます。
2. ダイアログの一番下の **コマンドをグローバル許可/拒否リストに追加 ›** を開きます。コマンドの候補が並ぶので、`agent-browser` とだけ書かれた行の右にある **✓(許可)** を押します。✓ は小さいので、**緑色に変わったこと**を確かめてください(変わっていなければもう一度押します)。
3. 続けて **タスクに対して承認** を押します。
4. 以降のコマンドは承認なしで進みます(実機確認では、この 2 つを最初に行った回は、それ以上承認を求められませんでした)。もし求められたら、同じように内容を読んで **タスクに対して承認** を押します。

> 「タスクに対して承認」の効果はこのタスクの間だけですが、**許可リストへの追加は Bob 全体の設定(すべてのワークスペース)に残ります**。ステップ8で必ず外します。

### プロンプト

Bob のチャットに、次のプロンプトを**そのまま貼り付けて**送信します。

```text
http://localhost:3000 で ToDo アプリが動いていて、私がすでに `agent-browser open http://localhost:3000/` でブラウザを開いてあります（既定のセッション）。agent-browser スキルを使って、そのブラウザを操作して次の E2E テストを実行し、結果をステップごとに PASS / FAIL で報告してください。

注意: `agent-browser open` と `--session` は使わないでください（開き直すとコマンドが戻らなくなります）。ページを最初からにしたいときは、テストを始める前に 1 回だけ `agent-browser reload` を使ってください（ステップ 2〜4 の途中では reload しないでください。一覧が空に戻ってしまいます）。最後にブラウザを閉じる必要はありません。ターミナルは PowerShell なので、`@e3` のような ref は必ず単一引用符で囲んで `'@e3'` と書いてください（囲まないと PowerShell が `@` を別の意味に解釈して失敗します）。

1. `agent-browser snapshot -i` で画面の要素を確認する
2. 入力欄に「牛乳を買う」と入れて「追加」を押す → 一覧に「牛乳を買う」が 1 件表示される
3. 入力欄に「レポートを書く」と入れて「追加」を押す → 一覧が 2 件になる
4. 「牛乳を買う」の行の「削除」を押す → 一覧に「レポートを書く」だけが残る（1 件）

各ステップの操作のあとに `agent-browser screenshot e2e-step1.png` のように、ステップ番号を付けた PNG を作業フォルダに保存してください（e2e-step1.png 〜 e2e-step4.png の 4 枚）。各ステップで期待どおりかを確認し、ずれがあればどのステップで何が違ったかを書いてください。報告の表には、ステップごとの PASS / FAIL と確認内容に加えて、保存した画像のファイル名を書いてください。画像以外のファイルは変更しないでください。
```

Bob は、`snapshot` で部品の番号を調べ、`fill`(入力)、`click`(クリック)、`get text`(文字の取得)、`get count 'li'`(行数)、`screenshot`(画像の保存)を組み合わせて 4 ステップを進め、最後に **ステップ / 結果 / 確認内容 / 画像** の表で報告します(4〜5 分かかります)。

- プロンプトに「ref は `'@e3'` と単一引用符で囲む」と書いてあるので、Windows の PowerShell でも最初から正しく入力されます(実機確認では失敗なし)。もし Bob が引用符を忘れて `fill` が失敗し、「引用符で囲んで再実行します」と言い直した場合は、失敗直後に撮った画像(一覧が空のまま)を言い直しのあとに撮り直しているかを、報告で確認してください。
- 統合ブラウザーに表示している ToDo 画面は変化しません。Bob が動かしているのは別の(見えない)ブラウザです。結果は Bob の報告で読みます。

## ステップ5:全部 PASS を確認し、画像で根拠を見る

Bob の表が 4 行とも PASS なら成功です。ただし、Bob が動かしたブラウザは画面に出ないので、**PASS の根拠を自分の目で確かめます**。Bob のエクスプローラー(左側)に `e2e-step1.png` 〜 `e2e-step4.png` ができているので、クリックして開きます。

| 画像 | 見えるはずのもの |
|---|---|
| `e2e-step1.png` | 入力欄・追加ボタン・「サンプルを読み込む」だけで、一覧は「タスクがありません。」 |
| `e2e-step2.png` | 一覧に「牛乳を買う」が 1 件 |
| `e2e-step3.png` | 「牛乳を買う」「レポートを書く」の 2 件 |
| `e2e-step4.png` | 「レポートを書く」だけが 1 件 |

Bob の報告と画像が合っていれば、E2E テストは「本当に」PASS です。報告は PASS なのに画像が前の状態のまま(たとえば `e2e-step2.png` の一覧が空)のときは、失敗した操作の直後に撮った画像が残っている可能性があるので、Bob に「e2e-step2.png を撮り直してください」と頼みます。FAIL があるときは、その画像と Bob の「確認内容」を見て、何が違ったかを講師に伝えてください。

**パターン1の人は、ここまでが自分で行う範囲です。** ステップ6〜7 は講師のデモを見ます(ステップ8 の後片付けは各自で行います)。

## ステップ6:バグ入りのファイルに差し替えて、E2E テストで見つける

**パターン2:** ここから先は、**講師の指示を待ちます**。

講師の合図が出たら、[共通準備の 5](../common-setup.md) の手順で、`bobathon-todo/scenario1-browser/bug/todo-logic.js`(シナリオ1と同じファイル)を作業フォルダの `todo-logic.js` に上書きコピーします。サーバーはリクエストのたびにファイルを読むので、**再起動は不要**です。

Bob に、次のように頼みます。

```text
todo-logic.js を別の版に差し替えました。`agent-browser reload` でページを読み直してから、さっきと同じ 4 ステップの E2E テストをもう一度実行し、ステップごとに PASS / FAIL を報告してください。画像は bug-step1.png 〜 bug-step4.png の名前で保存してください。FAIL があったら、期待した状態と実際の状態を書いてください。画像以外のファイルはまだ変更しないでください。
```

ステップ 1〜3 は PASS、**ステップ 4 だけ FAIL** になります。Bob は「期待: レポートを書く だけが残る / 実際: 牛乳を買う だけが残り、レポートを書く が消えた」のように、画面で起きたことを報告します。`bug-step4.png` を開くと、「牛乳を買う」だけが残った画面が見えます。シナリオ1のユニットテストが「`removeTodo` の戻り値が違う」と教えてくれたのに対して、E2E テストは「削除ボタンを押したら違う行が消えた」という**利用者から見た症状**を教えてくれます。

## ステップ7:Bob に直させる

```text
ステップ 4 が FAIL した原因を todo-logic.js を読んで調べ、直してください。直したら `agent-browser reload` して、同じ 4 ステップの E2E テストをもう一度実行し、全部 PASS になったことを確認してください。画像は fixed-step1.png 〜 fixed-step4.png の名前で保存してください。
```

Bob は `todo-logic.js` を読み、`removeTodo` の条件を直す差分(1 行だけ変わります)を示して承認を求めてきます。内容を読んで、納得できてから **一度だけ承認** を押します。続けて Bob が E2E テストを再実行し、4 ステップすべて PASS の表を出せば完成です。

## ステップ8:後片付け

1. ターミナル B で `agent-browser close` を実行して、見えないブラウザを閉じます。
2. ターミナル A をクリックして `Ctrl + C` を押し、サーバーを止めます。
3. **Bob設定** > **チャット** > **実行** の右端の矢印を開き、**許可されたコマンド** の一覧から `agent-browser` の行のごみ箱を押して削除します。これで、ステップ4の許可リストへの追加が元に戻ります(「タスクに対して承認」はタスクが終われば効果がなくなるので、戻す作業はありません)。

## 完成の確認

- [ ] ステップ4〜5で、Bob の E2E テストが 4 ステップとも PASS になり、`e2e-step4.png` に「レポートを書く」だけが残っている
- [ ] (パターン2)ステップ6で、ステップ 4 だけ FAIL になり、Bob が「どの行が残ったか」を報告した
- [ ] (パターン2)ステップ7で、1 行の修正のあと、4 ステップとも PASS に戻った
- [ ] ステップ8で、ブラウザとサーバーを止め、許可リストから `agent-browser` を削除した

## 振り返り

- 同じバグ(`removeTodo` の条件)を、シナリオ1のユニットテストと、E2E テストでは、それぞれどう「見つけた」でしょうか。どちらが原因の場所を特定しやすく、どちらが利用者への影響を説明しやすかったですか。
- E2E テストは、何を保証して、何を保証しないでしょうか(たとえば、画面の見た目、他のブラウザ、速さ)。
- Bob はスキルを読んでから道具を使いました。自分のチームの道具(社内 CLI、テスト環境)をスキルにするとしたら、何を書きますか。

## つまずきやすい点

| 症状 | 対処 |
|---|---|
| `agent-browser` が認識されない | [事前課題](../pre-assignment.md)の 4 をやり直す。ターミナルと Bob を再起動する |
| Bob設定 > スキル に `agent-browser` が出ない | 登録後に Bob を起動し直したか確認する。なければ[事前課題](../pre-assignment.md)の 5 をやり直す |
| `node server.js` が `EADDRINUSE` と表示する | 3000 番が使用中。前のサーバーが残っていないか確認し、ターミナル A で `Ctrl + C` してから起動し直す |
| Bob が「プロセスを待機中...」のまま進まない | Bob が `agent-browser open` を実行してしまった可能性。チャット右下の停止ボタンでタスクを止め、ステップ4のプロンプト(open と --session の禁止を含む)で新しいタスクとしてやり直す |
| Bob の `fill` が失敗する(Windows) | PowerShell の `@` の解釈によるもの。プロンプトの「`'@e3'` と囲む」の行が抜けていないか確認する。Bob が引用符を付けて再実行するなら、そのまま待つ |
| Bob が `agent-browser` 以外のコマンドの承認を求める | 内容を読んで、問題なければ一度だけ承認を押す |
| 画像ファイルができていない | Bob に「各ステップの画像を `agent-browser screenshot e2e-stepN.png` で保存してください」と頼む。エクスプローラーに出ないときは、作業フォルダ名の横の更新ボタンを押す |
| 「タスクに対して承認」を押しても次のコマンドで承認が出る | 許可リストの ✓ が緑になっていなかった可能性があります。もう一度「コマンドをグローバル許可/拒否リストに追加 ›」を開いて ✓ を確認し、「タスクに対して承認」を押す(2〜3 回で止まらなくなります) |
| 報告は PASS なのに画像が前の状態のまま | 操作が一度失敗して言い直したときに、失敗直後の画像が残っていることがある。Bob に「そのステップの画像を撮り直してください」と頼む |
| Bob が途中で「手順を間違えたのでやり直します」と言う | そのまま待つ。Bob は最初からやり直して、最後の実行の結果だけを表にします(報告にやり直した旨が書かれます) |
| 差し替えたのにステップ 4 が PASS のまま | ファイル名が `todo-logic.js` か、作業フォルダ直下か確認する。Bob に `agent-browser reload` を含めて頼んだか確認する |

ユーザー管理とセキュリティグループ | Maximo Manage オンボーディング

Maximo Manage のユーザー管理の仕組みと、セキュリティグループによる権限設定を学びましょう。

このページは 管理者向け です。

Manage のユーザー管理の仕組み

Maximo Manage のユーザー管理では、以下の4つの概念が登場します。初心者が最も混乱しやすいポイントなので、まず関係を整理しましょう。

概念場所役割
MAS UserMAS HubMAS へのログイン認証。AppPoint を消費する単位
Manage UserManage 内Manage アプリケーションへのアクセス権を持つユーザー
Person（人）Manage 内作業担当者・連絡先などの「人」の情報を管理するレコード
Security GroupManage 内アプリケーション権限・サイト権限をまとめたグループ

よくある混乱ポイント

「MAS Hub でユーザーを追加したのに Manage で使えない」 という場合、Manage 内のセキュリティグループ設定が未完了なことがほとんどです。MAS Hub と Manage はそれぞれ独立した設定が必要です。
症状原因対処
Manage にログインできないMAS Hub でアクセス権が付与されていないMAS Hub の「アクセスとライセンス」を確認
ログインできるがアプリが表示されないセキュリティグループの権限が不足セキュリティグループの「読み取り」権限を付与
People（人）アプリに出てこないPerson レコードが作成されていないManage 内で Person レコードを手動作成
作業指示の担当者に設定できないPerson レコードと User が紐づいていないPerson レコードの「User」フィールドにユーザー ID を設定
MAS Hub でのユーザー追加手順は MAS 共通ガイド — ユーザーの追加と権限設定 を参照してください。このページでは Manage 内の権限設定について説明します。

Manage のセキュリティグループとは

Manage のセキュリティグループは、どのアプリケーションをどのような操作で使えるかを定義したグループです。

ユーザーをセキュリティグループに所属させることで、そのグループに設定された権限が付与されます。1人のユーザーを複数のグループに所属させることもできます。

権限は以下の3つの観点で設定します。

観点内容
アプリケーション権限どのアプリケーションにアクセスできるか（読み取り・書き込み・削除など）
サイト権限どのサイトのデータにアクセスできるか
データ制限特定の条件に合うデータのみに絞り込む（例：自分のサイトの作業指示のみ）

サンプルグループを活用する

Manage には初期状態でサンプルのセキュリティグループが用意されています。
まずはこれらをベースにカスタマイズするのが効率的です。

サンプルグループ想定する役割主なアクセス範囲
MAXADMINシステム管理者全アプリケーション・全操作
MAXEVERYONE全ユーザー共通の基本権限基本的な参照・プロファイル編集など
Supervisor現場監督者作業指示・資産・スケジュール・承認など
Technician現場技術者作業指示の実施・労働報告・サービスリクエスト
Requester依頼者サービスリクエストの作成・確認のみ
Inventory Clerk在庫管理担当在庫・資材の受払・在庫カウント
これらはサンプルです。実際の業務に合わせてカスタマイズしてください。

セキュリティグループの設定手順

1. セキュリティグループを開く

Go To メニューから 「セキュリティ」 > 「セキュリティグループ」 を開きます。

2. グループを新規作成またはサンプルを複製

新規作成する場合：

  1. 「新規グループ」 をクリック
  2. グループ ID・説明を入力
  3. 各タブで権限を設定して保存

サンプルを複製する場合：

  1. ベースにするサンプルグループを開く
  2. 「アクション」 > 「グループの複製」 をクリック
  3. 新しいグループ ID を入力して複製
  4. 必要に応じて権限を調整

3. アプリケーション権限を設定する

「アプリケーション」タブ で、アプリケーションごとに権限を設定します。

上テーブルでアプリケーションを選択すると、下に 「Options for ○○」 テーブルが表示されます。各オプションの 「Grant Access?」 チェックボックスをONにして権限を付与します。「Grant Listed Options for This Application」 ボタンで一括付与も可能です。

権限オプション例（Assets の場合）内容
Read access to Asset参照のみ（Go To メニューへの表示にも必要）
New Asset新規レコードの作成
Save Assetレコードの編集・保存
Delete Assetレコードの削除
アプリケーションによっては、基本的な CRUD 権限に加えて、さらに詳細な機能権限（例：Add Assets to Collections / Duplicate Asset など）を設定できる3つ目のテーブルが表示されます。初期設定では基本権限のみ設定すれば十分です。
アプリケーションを Go To メニューに表示させるためには、最低限「Read access」権限が必要です。権限がないアプリケーションはメニューに表示されません。

4. ユーザーをグループに追加する

「ユーザー」タブ でユーザーを追加するか、ユーザーレコードからグループを割り当てます。

セキュリティの反映タイミング

セキュリティグループの変更は、対象ユーザーが次回ログイン時に反映されます。
即時に反映させたい場合は、「アクション」 > 「セキュリティーの適用」 を実行してください。

設定後は、テスト用アカウントで実際にログインして、意図した通りの権限になっているか確認することを推奨します。

詳細は公式ドキュメントへ

セキュリティグループの詳細な設定項目については、IBM 公式ドキュメント を参照してください。

1. 契約とアカウント

契約経路とプランを確認する

IBM Confluent Cloud の契約経路、無償トライアル、料金体系、SLA の条件を確認します。
最終更新: 2026/8/12

Step 1: 契約経路を確認する

IBM Confluent Cloud には次の契約経路があります。

経路概要
IBM 経由IBM Confluent Cloud（PID 5900-C3E）として契約します。ライセンス種別は International Program License Agreement、XaaS 区分です
クラウドマーケットプレイスAWS / Microsoft Azure / Google Cloud のマーケットプレイス経由で契約します。従量課金（Pay As You Go）またはコミット契約（Commits）を選択でき、クラウド利用費と請求を統合できます
Confluent への直接サインアップConfluent Cloud のサインアップページから自己登録します

いずれの経路で契約した場合も、利用者が操作する画面は Confluent Cloud Console（https://confluent.cloud）です。

Step 2: 無償トライアルの条件を理解する

新規に Confluent Cloud へサインアップした Organization には、400米ドル分の無償クレジットが自動的に付与されます。

項目内容
クレジット額400 USD
有効期限付与から30日
終了条件クレジットを使い切る、または30日が経過するかのいずれか早い方
リソースの作成支払い方法の登録が必須です（トライアル終了までは課金されません）
一時停止できません
期間の延長Confluent の営業担当者への依頼が必要です

トライアル期間中は、クレジットの50%を消費した時点、有効期間の50%が経過した時点、80%を消費した時点などに、サインアップしたユーザー宛に通知メールが送信されます。

【重要】トライアル終了後の挙動

トライアルが終了すると Organization はサスペンド（一時停止）され、機能の利用とデータへのアクセスができなくなります。再開するには、Confluent Cloud Console にログインして支払い方法を登録するか、プロモーションコードを適用します。

サスペンドから30日以内に対応しない場合、リソースは削除されます。（Organization とユーザーアカウントは保持されます。）

なお、支払い方法の登録およびプロモーションコードの適用には OrganizationAdmin ロールが必要です。

Step 3: 料金体系を理解する

IBM Confluent Cloud は消費量ベースの課金です。課金は1時間単位で発生し、1時間未満の利用も1時間として計上されます。すべての計算は UTC 基準で、月次の後払い請求です。リソースを作成した時点で課金が始まり、削除した時点で停止します。

主な課金ディメンションは、クラスター容量（eCKU または CKU）、データの ingress / egress、ストレージ、コネクター、ksqlDB、Flink、Tableflow、監査ログ、サポートです。

見積もり時に見落としやすい5つのポイント

  1. ストレージはレプリケーション後の総量で課金されます。 Confluent Cloud は高可用性のためにデータを3重化しているため、課金対象のストレージは書き込み量の約3倍が目安です。削減には Topic の retention.bytes および retention.ms の調整が有効です。
  2. ingress / egress にはリージョン係数が乗算されます。 日本リージョンの係数は公開価格表でご確認ください。
  3. すべてのデータ転送が課金対象です。 これには、Confluent Cloud Console のメッセージブラウザが表示のために発行するリクエストも含まれます。
  4. Produce (v3) REST API の利用には追加の ingress 料金が発生します。 リージョン係数の適用前に加算されます。
  5. Tableflow を有効にした Topic は、Kafka ストレージのレプリケーション分が課金されません。 最大で約67%の削減効果が見込まれます。

パーティション課金の扱い

現在は、いずれのクラスタータイプでもパーティション数自体は課金対象ではありません。ただし、パーティション数は eCKU の消費量に影響します。

一方、旧課金モデル（レガシー）の Basic / Standard クラスターではパーティション課金が残っており、Basic は10パーティション、Standard は500パーティションが無償枠です。Enterprise クラスターにはパーティション課金がありません。

【参考】 Basic / Standard は 2024年4月にパーティションベース課金から eCKU ベース課金へ移行しています。それ以前に作成された Organization は旧モデルのままの場合がありますので、既存環境の請求を分析される際は、どちらのモデルが適用されているかを最初にご確認ください。

参考：Billing Dimensions in Confluent Cloud（英語）

Step 4: SLA の条件を確認する

IBM Confluent Cloud は 99.99% の稼働率 SLA を提供していますが、この水準を得るには構成上の条件があります。

クラスタータイプ99.99% SLA の条件
Basic対象外です。より高い SLA が必要な場合は Standard へアップグレードします
Standard / Enterprise最小 2 eCKU が必要です
DedicatedMulti-Zone 構成が必要です

Stream Governance の Advanced パッケージにも 99.99% の SLA が設定されています。

なお、クラスター作成画面では Uptime SLA を 99.9% と 99.99% から選択する形になっており、99.99% を選択すると最小 eCKU が 2 に自動設定されます。また、99.9% で作成した Standard クラスターは、作成後もクラスターの Settings タブから 99.99% へアップグレードできます。

クラスタータイプの選択については クラスタータイプを選択する をご確認ください。

リージョンを選択する

日本国内で利用可能なリージョンと、機能ごとの提供状況の確認方法を説明します。
最終更新: 2026/8/12

Step 1: 日本国内のリージョンを確認する

IBM Confluent Cloud は AWS、Microsoft Azure、Google Cloud 上で稼働します。日本国内に該当するリージョンは次のとおりです。

クラウドリージョンコード所在
AWSap-northeast-1東京
AWSap-northeast-3大阪
Microsoft Azurejapaneast / japanwest東日本 / 西日本
Google Cloudasia-northeast1 / asia-northeast2東京 / 大阪

一覧にないリージョンについては、Confluent へのリクエストが可能です。

クラスター作成画面の「Provider and region」でクラウドを選択すると、そのクラウドで利用可能なリージョンの一覧が表示されます。表示されるリージョンは、選択しているクラスタータイプによって変わります。

Step 2: 機能ごとの提供状況を確認する

【重要】リージョンの提供状況は機能ごとに異なります

クラスタータイプ、Apache Flink、Tableflow、ネットワークオプション（PrivateLink、VPC / VNet Peering、Transit Gateway）、マネージドコネクター、Stream Governance は、それぞれ対応するリージョンの範囲が異なります。「東京リージョンが使える」ことと「東京リージョンで目的の機能が使える」ことは別ですので、必ず個別にご確認ください。

対応リージョンは頻繁に更新されるため、ドキュメントの表だけでなく、実際の画面や API で確認することをおすすめします。

対象確認方法
Kafka クラスター全般Confluent Cloud Console のクラスター作成ウィザードで、リージョンの選択肢を確認します
Apache FlinkConfluent Cloud Console（Flink → Compute pools → Add compute pool）、Confluent CLI、または Flink REST API の Regions エンドポイントで確認します
TableflowAWS では Flink がサポートされている全リージョンで利用できます。Microsoft Azure（Azure Data Lake Storage Gen2）でも一般提供されています

【参考】可用性ゾーンの選択

クラスター作成時に、シングル AZ とマルチ AZ のいずれかを選択します。99.99% の SLA を得るには、Standard / Enterprise では最小 2 eCKU、Dedicated では Multi-Zone 構成が必要です。詳細は 契約経路とプランを確認する をご確認ください。

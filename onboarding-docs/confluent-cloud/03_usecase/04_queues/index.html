キューイング用途で利用する

Queues for Kafka（share group）を利用して、従来のメッセージキュー相当のワークロードを統合します。
最終更新: 2026/8/12

Queues for Kafka とは

Queues for Kafka（KIP-932）は、従来のメッセージキュー製品が担ってきたワークロードを、データストリーミング基盤に統合するための機能です。一般提供が開始されています。

従来の Consumer Group では「パーティション数とコンシューマー数が 1:1」という制約がありましたが、新しい share group および share consumer の仕組みにより、複数のコンシューマーが同一 Topic のメッセージを協調して処理できます。これにより、パーティション数を超えた弾力的なスケールが可能になります。

適した用途

次のような、メッセージ単位の確認応答（ack）、パーティションの並列消費、パーティション数を超えるスケールを必要とするワークロードに適しています。

  • コマンドの実行
  • サービス間通信
  • タスクの実行
  • ワークキュー
  • ジョブ処理

【重要】対応するクラスタータイプ

Queues for Kafka は Enterprise および Dedicated クラスターで利用可能です。Standard クラスターへの対応は 2026年下半期の予定とされています。

キューイング用途を前提とする場合、この制約はクラスタータイプの選定に直接影響します。クラスタータイプを選択する と併せてご検討ください。

運用時の可視化

Confluent Cloud Console には share group 専用の画面があり、コンシューマーの健全性とグループの状態を確認できます。また、Metrics API からキュー固有のメトリクスを取得できるため、オートスケールの判断に利用できます。

ODBC Data Connector の構成

ODBC Data Connector の構成
最終更新: 2026/8/2

本ガイドは、2024年10月21日に公開された PAaaS Configure Database access（英語） の内容を基にしています。
PAoC 版ガイドの「Satellite Connector Agent の構成」に相当するページです。PAaaS（TM1 Database 12）におけるリレーショナルデータベース連携は、Planning Analytics ODBC Data Connector が担います。
Connector の配置要件・構成手順は変更される可能性があるため、IBM の最新ドキュメントを必ずご確認ください。

概要

TM1 Database 12 では、データベースが直接 ODBC ドライバーを使用しません。TurboIntegrator（TI）プロセスで ODBC データソースを開く際、TM1 Database 12 は Planning Analytics ODBC Data Connector（ODBCIS とも呼ばれます）に接続してクエリーを実行します。Connector はお客様環境内のマシンに配置され、ローカルの ODBC データソースを OData 準拠の REST API サービスに変換する「翻訳者」として機能します。

データベース直結には、ファイル抽出・転送・ロードの待ち時間なしに最新データをオンデマンドで取得できる、開発時に SELECT 文の変更だけで済む、ドリルスルー（drill to detail）でプランニング上の数値の内訳を基幹システム側の明細で確認できる、といったメリットがあります。

前提要件（Windows 版）

  • OS：Windows 10 以降 / Windows Server 2016 以降
  • リソース：OS と ODBC ドライバーの必要分に加えて 4 コア・4GB メモリー以上
  • 対象データソースへの全 ODBC ドライバーを同一マシンに構成（1つの Connector で複数の PAaaS データベースに対応可能）
  • 対象データベースへのネットワーク経路と、HTTP/S の受信接続
  • PAaaS からの接続は有効な証明書による HTTPS のみ（自己署名証明書は信頼されません）。証明書は Connector 自体に設定するか、境界（WAF・リバースプロキシ等）で SSL 終端します。

出典：Importing data to TM1 Database 12 with the Planning Analytics ODBC Data Connector（IBM Docs）

構成手順（概要）

  1. ダウンロード：PAW の管理タイル → Databases → 画面右上のダウンロードアイコン → ODBC Data Connector。

  1. 展開と初期化：zip のプロパティで「ブロックの解除」を行ってから任意のディレクトリに展開し、StartStandaloneODBCIS.bat を一度実行して構成ファイルを生成します。
  2. 構成：deployment/config.odbcis.json を編集します。Datasources セクション（ODBC DSN ごとの接続情報）、Clients セクション（PAaaS 側から使う ID/Secret と、アクセスを許可するデータソースの一覧）、チューニングパラメーターの3部構成です。パスワードは次回起動時に自動暗号化されます（変更時は PasswordEncrypted/SecretEncrypted を false に戻して編集）。Clients の分離により、HR と Finance で参照可能なデータソースを分けるといった設計が可能です。ポート変更は config.internal.json の serverPort で行います。
  3. 起動：スタンドアロン実行、または InstallODBCISWindowsService.bat で Windows サービスとして登録します。
  4. PAW 側の接続設定：管理タイル → Databases → 対象 DB → Configuration タブ → Administration → External databases で ODBCServiceRoot を設定します。形式は HTTPS://<ID>:<Secret>@<公開ドメイン>:<ポート>/api/v1（認証情報埋め込み）または HTTPS://<公開ドメイン>:<ポート>/api/v1（TI プロセス側で ID/Secret を入力。プロセスごとに別資格情報を使い分け可能）のいずれかです。

  1. テスト：TI プロセスのデータソースとして DB 接続を選択し、SQL のプレビューで疎通を確認します。

ネットワークの留意点

  • ファイアウォールルール：Connector で構成したポートへの HTTPS 受信を許可する必要があります。接続元を PAaaS のエンドポイントに限定する場合は、IBM Docs の「Egress IP addresses」トピックを参照してください。
  • Connector の設定は、同梱アーカイブ展開後の構成ファイル（/deployment/config.odbcis.json 等）で調整します。

その他のデータ取り込み手段

  • ファイルアップロード（CSV 等）＋ TI プロセスによる取り込み・変換
  • REST API / TM1py：API キーによるプログラム連携（認証と IBMid 参照）

💡 テキストファイルの利用：Microsoft の ODBC テキストドライバーで DSN を作成し、ODBC Data Connector 経由で PAaaS の外部に置いたテキストファイル（CSV 等）をデータソースとして利用できます（元記事の「Using Text Files with ODBC Data Connector」参照）。ただし元記事の筆者注として、テキストドライバーの複雑な SQL への対応は未検証であり、シンプルなファイル取り込み向けとされています。

💡 クラウドオブジェクトストレージ（Amazon S3 等）を TI プロセスのデータソースとして直接指定できるかどうかは、IBM の最新ドキュメントでご確認ください（移行ユーティリティの出力先としての S3 は対応しています）。

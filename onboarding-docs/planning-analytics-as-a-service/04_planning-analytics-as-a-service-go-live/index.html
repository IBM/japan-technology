本番稼働（Go Live）

本番稼働（Go Live）
最終更新: 2026/8/6

本ガイドは、2024年10月18日に公開された Go Live consideration for Planning Analytics as a Service（英語） の内容を基にしています（PAoC 版 Go Live ガイドと共通の枠組みです）。
Go Live のプロセスはお客様・プロジェクト・社内手順によって異なります。本ページは検討すべき事項の枠組みの提案です。
手順や画面が本ガイドと一致しない場合は、IBM の最新ドキュメントや公式ガイドラインを必ず参照し、最新版に沿った対応を行ってください。

本番稼働前の準備

Go Live 前に検討すべき領域として、以下のようなものがあります（ただしこれらに限りません）：

  • 成功の定義：関係者からのフィードバックを収集する方法を決める
  • タイムラインとタスクの整理：各タスクとその期限を明確にする（タスクごとにオーナーを割り当て、他タスクへの依存関係があれば明記する）

例：

  • 必要なユーザーの端末に PAfE 2.1.14 以降がインストールされていることを確認する → PAfE の設定
  • 最新のデータを本番環境（Production 環境のデータベース）に移行する → 移行または新規作成
  • ユーザーを追加（IAM＋PAW）し、適切なロール・グループに割り当てる → 管理概要
  • データベースセキュリティ（オブジェクト／セル）を本番モデルに対して構成する
  • データフローやモデルロジックに関する全テストケースを完了し、パフォーマンスを確認する
  • ユーザーのトレーニングおよび受け入れテスト（UAT）が完了していること
  • 自動バックアップを有効化し、リストア手順を確認しておく
  • Environment Quota タイルでユーザー数・RAM・ストレージの残量を確認し、本番運用の負荷に備える → 管理概要
  • 変更管理プロセスが合意されていること
  • すべての関係者に対してスケジュールが共有されている
  • 障害時対応（コンティンジェンシープラン・ロールバック）が策定されている
  • 新しいプロセスに基づくドキュメント・ガイドライン・ユーザーガイドを用意し、提供できる状態にしておく
  • 重要通知の購読：
    • IBM Community（PAaaS 101（英語））で最新情報や質問をキャッチできるようにする
    • SaaS Console のステータスページをブックマークしておく（ログインするとメンテナンス予定・アナウンスの詳細を確認可能）。PAaaS 101 からもステータス・メンテナンス通知を購読できる
    • Security Bulletins / My Notifications を購読する

コミュニケーションの重要性

本番稼働にあたっては、ユーザーへの連絡が極めて重要です。最低限、以下を含むメール（または他の方法）を送ることをおすすめします：

  • 招待を受け取った際に何が起きるか（IBMid 作成手順を含む。スクリーンショットを添えると親切）
  • 問題があった場合の連絡先
  • PAaaS 本番環境の URL（Data Center URL / tenantId 付き）
  • PAfE 用の接続情報（必要な場合）
  • 本番切り替えの時刻（および想定されるダウンタイム）

旧環境（オンプレミス / PAoC）から移行する場合の留意点

  • ユーザーが旧システムにアクセスできないように、ファイアウォールなどでブロックする方法があります。これにより、必要に応じて旧環境に一時的にアクセス可能にしておくことも可能です。
  • 別の方法としては、旧環境のサービスを停止し、アクセスできなくする手段もあります。
  • 旧システムを参照用に残す場合は、データベースを読み取り専用に設定することで、移行後のデータ検証にも使えます。

Go Live 当日

  • 旧環境からの移行であれば、旧システムへのアクセスを遮断または読み取り専用化する
  • PAaaS が稼働を開始したことを関係者全員に通知する（環境 URL・問い合わせ先を含めると効果的）
  • Users & Groups 画面で、ユーザーが招待を受け入れているか（Pending 状態の有無）を確認する。ユーザーを選択すると最終ログイン時刻も確認できます

  • 管理ページのデータベース状態（Healthy / Concern / Critical）でシステムのパフォーマンスを監視する

本番稼働後（Post Go Live）

  • 関係者からのフィードバックを収集する
  • 成功基準に照らして評価する
  • 管理ページの Environment Quota で RAM・ディスク・ユーザー数の使用量を定期的に監視する
  • 第二フェーズ（活用拡大・モダナイゼーション等）に向けた計画を立てる
  • 旧環境から移行した場合、データのバックアップと旧システムの廃止（ディコミッション）を実施する
  • 継続運用：新機能情報（IBM Docs・日本語）などのリリースノートを定期確認する（TM1 Database 側の更新に伴い PAfE の最低バージョン要件が引き上がる場合があります）

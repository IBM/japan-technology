Planning Analytics as a Service

よくあるご質問（FAQ）

よくあるご質問（FAQ）
最終更新: 2026/9/21

Planning Analytics as a Service（PAaaS）のオンボーディング・移行でよくいただくご質問をまとめています。多くは、従来の TM1（v11）／PAoC の運用経験を PAaaS に当てはめた際に生じる疑問です。
手順や画面が本ガイドと一致しない場合は、IBM の最新ドキュメントや公式ガイドラインを必ず参照し、最新版に沿った対応を行ってください。

ファイル・データ連携

Q1. 共有フォルダーに FTP／FTPeS／SFTP でアクセスできますか？

できません。 プロトコルの制限ではなく、PAaaS はフルマネージド SaaS として、お客様がファイルシステムへ直接アクセスする経路自体を提供していません（PAoC の共有フォルダーに相当する仕組みはありません）。ファイルの受け渡しは、ファイルマネージャー（Web UI）、TI プロセスのアップロード機能、または REST API（HTTPS＋API キー。SFTP スクリプトに相当する自動連携が可能）をご利用ください。

参考：ファイルの管理

Q2. TI プロセスでファイルのパスはどのように指定しますか？（v11 の '\\data\prod\...' が使えません）

v11 のような OS のフルパス指定は存在しません。事前にファイルマネージャーへファイルをアップロードしておき、プロセスエディターの Data source で「File」→「Select file」からファイルを選択します（パスの手入力は不要です）。スクリプトで動的に指定する場合は、ファイルマネージャーのルートからの相対参照（例：InterfaceFile/Transaction.csv の形）となります。まず Select file で一度選択し、プロセスが保持するデータソース名の形式を確認してから変数指定することをお勧めします。なお、Database Migration Utility は TI のデータソースパスを自動では書き換えないため、移行したプロセスは修正が必要です。

参考：ファイルの管理／移行または新規作成

Q3. ドライブ・エクスプローラーがメニューに表示されません。有効化の方法は？

ドライブ・エクスプローラーは PAaaS では提供されていません（表示されないのが正常な動作で、設定・権限の問題ではありません）。同機能はサーバーのファイルシステムやファイル共有へアクセスするための機能で、PAoC／PAW Local を対象としています。PAaaS でのファイル操作は Workbench のファイルマネージャーをご利用ください。

参考：ファイルの管理

Q4. 基幹システムの RDBMS（Oracle／SQL Server／Db2 等）と接続するには？

Planning Analytics ODBC Data Connector を、データソースに到達可能なお客様側マシンに配置して接続します。TM1 Database 12 はこの Connector を経由して ODBC データソースへクエリーを実行します。PAaaS からの接続は有効な証明書による HTTPS のみ（自己署名不可）など前提要件がありますのでご注意ください。

参考：ODBC Data Connector の構成

ログ・運用

Q5. tm1server.log やプロセスエラーファイルはどこで参照できますか？

Web UI から参照・ダウンロードできます。Workbench → 対象データベースの Processes セクションの3点リーダー（⋮）→ Error Logs を選択すると、ファイルマネージャーが開き、TM1 のログファイル一覧（tm1server.log、プロセスエラーファイル等）が表示されます。各ログはダウンロードまたはプレビューで確認します。なお、サーバーログ・トランザクションログの参照にはデータベースの管理者権限が必要な場合があります。

参考：Access to Server Logs through Modeling Workbench in PAW（IBM Community・英語）／View Logs in Planning Analytics as a Service（ExploringTM1・英語）

Q6. tm1s.cfg はどこにありますか？パラメーターはどう変更しますか？

PAaaS では tm1s.cfg をファイルとして直接編集することはできません。データベースの構成パラメーター（計算・パフォーマンス・外部データベース関連等）は、管理タイル → Databases → 対象 DB → Configuration タブから Web UI で変更します。また、Websheet（Spreadsheet Services）関連の設定は環境単位で編集できます。v11 の一部パラメーターは v12 で廃止・変更されている点にもご注意ください。

参考：管理概要／Changed features and components in TM1 Database 12（IBM Docs・英語）

Q7. バックアップはどのように取得・リストアしますか？

データベースごとに自動バックアップ（実行時刻を UTC で指定）とオンデマンドバックアップ（Standard / Premium プラン）を利用できます。バックアップ（.tgz）はダウンロード可能で、別のデータベース・別の環境へアップロードしてリストアすることもできます（環境間のデータ移送にも利用できます）。

参考：管理概要／移行または新規作成

Q8. 管理ページのデータベースの「アクティビティー」タブに何も表示されません。ログイン中のユーザーはどう確認しますか？

「結果がありません」は正常な動作です。TM1 Database 12 のアクティビティータブは「現在処理中のリクエスト（ジョブ）」だけを表示する仕様で、ログインしているだけで操作していないユーザーは表示されません。v11 ではスレッドが永続接続に対応していたため Threads タブにログイン中ユーザーが見えていましたが、v12 はリクエストを複数レプリカで処理するため、スレッドはリクエストの間だけ存在します。v12 に「ログイン中ユーザー一覧」を常時表示する画面はなく、目的に応じて次の手段を使います。

  • 誰がいつログインしたか：管理タイル → Users & Groups で各ユーザーの最終ログイン時刻を確認
  • ログインの履歴：サーバーログ（tm1server.log）に既定で記録。Workbench → Processes の3点リーダー → Error Logs から参照・ダウンロード（データベース管理者権限）
  • 今この瞬間の実行状況：アクティビティータブ、または Workbench でデータベースを右クリック → Activity（TM1 REST API の GET /Jobs でも取得可）

参考：The difference in design between PAW Administration v11 Threads tab and v12 Activity tab（IBM Support・英語）

Q9. v11 の監査ログ（AuditLogOn）に相当する機能はありますか？

ありません。 IBM Docs のパラメーターリファレンスに「AuditLogOn は TM1 12 には適用されない」と明記されており、PAaaS に v11 相当の監査ログ機能（メタデータ変更・セキュリティ変更・ログインの自動記録と専用照会画面）は提供されていません。IBM 製品担当の見解も踏まえた、目的別の代替手段は次のとおりです。

監査の目的手段
データの変更履歴（誰がどのセルをいつ変えたか）トランザクションログ（キューブロギング）。Workbench の Error Logs 導線から参照
ログイン・TI 実行の記録サーバーログ（tm1server.log）。同上
誰がいつアクセスしたか（直近）Users & Groups の最終ログイン時刻
ブック等の資産のリリース履歴Lifecycle Management の履歴
メタデータ（次元・ルール・プロセス等）の変更追跡Git リポジトリ連携によるバージョン管理（IBM 推奨。Standard / Premium）

注意点として、サーバーログ等のログは IBM 側のインフラで保管・管理され、お客様が保持期間を設定することはできません。監査証跡として一定期間さかのぼる必要がある場合は、ログを定期的にダウンロード（または REST API で取得）して自社で保管する運用を推奨します。また、Git 連携はモデラーが Push した時点の差分を記録するバージョン管理の仕組みであり、全操作を自動記録する監査ログではない点にご留意ください。

参考：AuditLogOn（IBM Docs・英語）／運用開始後のリリース管理（Git リポジトリ連携）

クライアント・移行

Q10. TM1 Architect／Perspectives は使えますか？

使えません。 Architect／Perspectives／TM1 Applications／Performance Modeler／Cognos Insight などのレガシークライアントは、PA 2.1 以降に含まれず、TM1 Database v12 ベースの PAaaS でも提供されません。モデリング・管理は Planning Analytics Workspace（Workbench）、Excel 作業は Planning Analytics for Microsoft Excel（PAfE）をご利用ください。

参考：その他のコンポーネント／IBM Planning Analytics 2.0 vs 2.1（TM1 Forum・英語）

Q11. PAfE はどのバージョンを使えばよいですか？

PAaaS の管理画面（Excel and Customizations）から配布される最新の 3.1 系をご利用ください（2025年10月以降、PAaaS 向け PAfE は 3.1 系の番号体系です）。2.1 系／2.0.x 系のクライアントを使用する場合、TM1 Database 12.5 以降の PAaaS では 2.1.14 以降が必須です（3.1 系はすべてこの要件を満たします）。

参考：PAfE の設定ガイド

Q12. v11 からの移行で「自動では移らないもの」は何ですか？

Database Migration Utility はデータベース本体を変換しますが、以下は自動では移行されません。移行計画に必ず織り込んでください。

  • 名前に無効文字（\/:*?"<>|';,）を含むオブジェクト、およびサンドボックス
  • TI プロセスのデータソースパス（Q2 のとおり修正が必要）
  • v12 で廃止・変更された機能に依存する実装（公式一覧の事前確認を推奨）
  • Planning Analytics Workspace のブック等の資産（Lifecycle Management で別途移行）

参考：移行または新規作成／Deprecated features and components in TM1 Database 12（IBM Docs・英語）

環境・権限

Q13. SaaS Console にインスタンスが1つしか表示されません。DEV 環境は IBM が作成するのですか？

インスタンスが1つだけ表示されるのは正常です。PAaaS はお客様によるセルフプロビジョニング方式で、IBM 側が Prod／DEV などの環境を作成する工程はありません（PAoC で IBM が PROD／DEV インスタンスを構築して Welcome Kit で引き渡す方式とは異なります）。お客様のサブスクリプション管理者が SaaS Console でインスタンスを作成すると、インスタンス名と同名の環境が1つだけ自動作成され、DEV 等の追加環境はお客様の管理者（Environments admin 権限）が PAW の管理タイル → Environments タイル → Add から作成します。なお、複数環境（開発／本番）の構成は Standard / Premium プランの機能です。Essentials をご契約の場合は、まずプランをご確認ください。環境の有無は、画面右上の環境セレクター（そのユーザーがアクセスできる環境のみ表示）ではなく、Environments タイル（インスタンス内の全環境を表示）で確認してください。

参考：プロビジョニング／管理概要

Q14. Prod 環境から DEV 環境へ資材を移す手順の全体像を教えてください。

大きく次の流れになります。

  1. 契約プランの確認：複数環境の構成とオンデマンドバックアップは Standard / Premium プランの機能です。
  2. リソース残量の確認：Environment Quota タイルで、DEV 用データベースに割り当てる RAM・ディスクの残量を確認します（クォータは全環境合算）。
  3. DEV 環境の作成：管理タイル → Environments → Add（環境名とタイプ Development）。
  4. DEV 環境へのユーザー追加：ユーザーは環境ごとに管理されるため、Prod に登録済みでも DEV へ追加が必要です。
  5. DEV 環境にデータベースを作成：Prod と同名で作成すると、ブック等の参照修正が不要になります。DEV 用途では HA をオフにすると RAM クォータを節約できます。
  6. データベースの移送：Prod でバックアップ作成→ダウンロード→DEV の Backup タブへアップロード→リストア。リストア後、DEV 環境の Workspace グループをデータベースのセキュリティグループへ再割り当てします。
  7. PAW 資産の移送：ブック・ビュー・Apps & Plans はデータベースのバックアップに含まれないため、Lifecycle Management で別途デプロイします。
  8. 検証：データ・セキュリティ・ブック動作、ファイルマネージャー上のファイル、ODBC Data Connector の接続先（DEV 用データソースへ向け直す）を確認します。

参考：移行または新規作成／管理概要

Q15. サブスクリプション管理者、PAW の管理者、データベースの管理者は何が違いますか？環境作成や移行に必要な権限は？

PAaaS の権限は独立した3層で構成されます。

層権限管理場所主な役割
1サブスクリプション管理者IBM SaaS Console契約・課金の確認、インスタンス作成、Console 利用者の管理
2PAW ロール（Administrator / Modeler / Analyst / Consumer）＋ Environments adminPAW 管理タイル（環境ごと）ユーザー・DB・環境・バックアップ・Lifecycle Management の管理
3データベースのセキュリティグループ（ADMIN / DataAdmin / SecurityAdmin 等）Workbench（データベースごと）モデル内のオブジェクト・データへのアクセス制御
  • 環境の作成・削除：PAW Administrator ＋ Environments admin 権限。インスタンス作成者には自動付与されますが、後から追加されたサブスクリプション管理者には自動付与されません（既存の PAW Administrator がユーザー詳細画面の Environments admin privileges を有効化します）。
  • 環境間の移行（バックアップ方式・Lifecycle Management）：移行元・移行先の両環境での PAW Administrator ロールが必要です。サブスクリプション管理者権限や Environments admin は不要で、データベースの ADMIN グループのみでは管理タイルが表示されないため実施できません（リストア後の検証・セキュリティ再設定には ADMIN グループが必要）。

参考：管理概要／認証と IBMid

運用・リリース管理

Q16. PAoC のような月次メンテナンス時間帯はありますか？時間帯の指定や、メール通知はできますか？

  • 更新の頻度：Planning Analytics Workspace（3.1 系）はおおむね月次で機能更新が適用され、Planning Analytics for Excel と TM1 Database 12 の更新はこれとは独立に通常月1回程度リリースされます。
  • 時間帯の指定：PAoC のようにお客様が月次のメンテナンス枠を指定する仕組みは、PAaaS では提供されていません（IBM が SaaS としてスケジュール・適用します）。固定の曜日・時間帯は公開情報としては提示されておらず、個々のメンテナンスは事前にステータスページへ掲載されます。契約上の取り決めについては IBM 営業窓口にご確認ください。
  • 通知の受け取り：通知は購読（オプトイン）制です。利用ユーザー全員に自動でメールが届く仕組みではなく、ステータスページで登録した方にメールが届きます。管理者が代表して購読し、社内に展開する体制をお勧めします（担当交代に備えて複数名での購読を推奨）。
  • 確認先：SaaS Console ステータスページの Planned maintenance タブ（履歴から過去の実施パターンも把握できます）、および PAaaS 101 の「Upcoming Maintenance」。

参考：サポートについて

Q17. DEV で改修した TI プロセス1本だけを Prod へリリースするには？（資材の部分リリース）

資材の種類によって手段が異なります。

  • Workspace の資産（ブック・ビュー・フォルダー・Applications・Plans）：Lifecycle Management で対象を選んで部分的にデプロイできます。
  • TM1 データベースのオブジェクト（TI プロセス・ルール・次元・キューブ・チョア）：Lifecycle Management の対象外です。次のいずれかで行います。
    1. Workbench での手動移送：DEV のプロセスエディターの内容を Prod 側へ反映（少量・臨時向け。プロセスエディターの Diff view が差分確認に有用）。
    2. TM1 REST API／TM1py による自動化：DEV の定義を取得して Prod へ登録するスクリプトを用意（繰り返しリリース向け。再現性・記録性を確保できます）。
    3. Git リポジトリ連携によるデプロイ（PAaaS の TM1 Database 12 で正式サポート。Standard / Premium）：Workbench のデータベースを右クリック → Git メニューから、GitHub / Azure DevOps / AWS CodeCommit のリポジトリへオブジェクト（キューブ・次元・ルール・プロセス等）を Push し、別環境で Pull して反映します（本格的なリリース管理向け。バージョン管理も兼ねます）。Push にキューブのデータや次元の属性は含まれない点に注意してください。
  • プロセスのデータソース（ファイル・ODBC 接続）は環境ごとに異なるため、リリース時の置き換えに注意し、リリース前に Prod のオンデマンドバックアップを取得しておくことを推奨します。

参考：運用開始後のリリース管理（Git リポジトリ連携）／管理概要（Lifecycle Management）／Git repository integration for Planning Analytics database objects（IBM Docs・英語）／Use Git repository integration to manage Planning Analytics database objects（IBM Docs・英語）

サポート

Q18. お客様のサポートケースを、パートナー企業のメンバーも起票・参照できるようにするには？

手順の向きは「パートナーのメンバー自身が申請 → お客様側の管理者が承認」です（お客様側で IBMid を登録するのではなく、承認のみを行います）。

  1. 事前にお客様から IBM お客様番号（ICN：0 で始まる 7 桁）を共有してもらいます。
  2. 各メンバーが IBMid で IBM サポートポータルにログインし、右上の人型アイコン → Support Access → Request Access を選択します。
  3. Product manufacturer／Product（IBM／Planning Analytics）、Customer number（ICN）、Country、申請理由（日本語可）を入力して Submit します。
  4. お客様側のサポートアカウント管理者（承認権限者）が承認すると、お客様の権利に基づくケースの起票・参照が可能になります。

参考：「サポート・サイト」のユーザー登録（IBM Support・日本語）

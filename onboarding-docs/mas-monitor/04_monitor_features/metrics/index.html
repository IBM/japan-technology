Monitor の主な機能

メトリクスの設定とデータ確認 | Maximo Monitor オンボーディング

センサーから送られるデータ項目（メトリクス）を定義し、Monitor でデータが受信できているか確認しましょう。

このページを始める前に

メトリクスを定義してデータを確認するには、センサーから Monitor への データ連携（接続） が必要です。 現時点での状況に合わせて、このページの進め方が変わります。

状況このページでできること
データ連携あり（実デバイス／API 接続済み）メトリクスを定義し、実際にデータが届いていることを確認する
データ連携なし（まだ接続準備中）サンプル値でメトリクスを登録し、次のダッシュボードページで動作を体験する

どちらの場合も、まずはメトリクスの登録から始めましょう。

メトリクスとは

メトリクスは、デバイスから Monitor に送られてくるデータ項目です。 温度・圧力・振動・回転数など、センサーが計測する各値がメトリクスとして管理されます。

Monitor では2種類のメトリクスを扱います。

種類内容例
Raw metric（生メトリクス）イベントに直接紐づくメトリクス。関数を実行せず、受信したデータをそのまま扱う現在の温度、現在の圧力、累計稼働時間
Calculated metric（計算済みメトリクス）生データに関数を適用して導出するメトリクス平均温度、しきい値超過フラグ

オンボーディング段階では、まず Raw metric（生メトリクス） の定義から始めましょう。

Raw metric（生メトリクス）の定義手順

  1. 「Setup」 メニューを開き、「Device types」 タブを選択する
  2. 以下のいずれかの方法でデバイスタイプの編集画面を開く
    • デバイスタイプ名の横にある 「⋮」 をクリックし、「Edit」 を選択する
    • デバイスタイプ名をクリックして選択した状態で、右上の 「Edit（鉛筆アイコン）」 をクリックする

  1. 「Metrics」タブ を開く

  1. 画面右上の 「Add metric」 をクリックする

  1. 表示されたダイアログでもう一度 「Add metric」 をクリックする
  2. 以下の情報を入力する
項目内容サンプル値（データ連携なしの場合）
Metricセンサーが送信するメトリクス名と一致させるtemperature / humidity
Display name画面上に表示する名称。未入力でも可—
Event既存の event を選択する。まだ event が届いていない場合は event 名を手入力するsensor_event（2つとも同じ）
Type画面で選択できる型を指定するNUMBER
Unit任意℃ など
データ連携がまだの方は上のサンプル値で登録しておきましょう。次のページのダッシュボード作成でそのまま使います。Type のデフォルトは LITERAL です。NUMBER に変更するのを忘れずに。
  1. 「Add」 をクリックする（temperature と humidity の2つ分、手順5〜7を繰り返す）
  2. 全てのメトリクスを追加し終えたら、画面右上の 「Save」 をクリックして保存する

「Add」だけでは保存されません。 最後に必ず 「Save」 をクリックしてください。Save を押さずに画面を離れると、追加したメトリクスが破棄されます。
Raw metric は必ず event と関連付けて作成します。A metric is always associated with an event. と表示される通り、Event は必須項目です。
Metric 名はセンサーが実際に送信する名前と完全に一致している必要があります。Event を手入力する場合も、後から受信する event 名と一致していないと自動的に関連付けられません。大文字・小文字を含め、実際に送信される名前に合わせて正確に入力してください。
実際にデバイスまたは API からデータを送信できる場合は、次のページでダッシュボードを作成したあと、値が表示されることを確認してみましょう。値が見えたら、Monitor の最初の成功体験です。

データが届いているか確認する（データ連携ありの場合）

メトリクスを定義したら、Monitor にデータを届かせて受信を確認します。 データを送る方法は、環境によって以下の2つがあります。

方法対象
実デバイスから送信センサー側の接続設定が完了している場合
API でテスト送信Postman 等でリクエストを送れる場合
どちらの方法も用意できていない場合は、このセクションはスキップして次のページ（ダッシュボードの作成）に進んでも構いません。データが届いた段階で改めてここに戻って確認できます。

方法1：実デバイスから送信する

センサー側の接続設定（API キー・証明書など）が完了していれば、デバイスが自動的にデータを送信します。接続設定については IT 担当者または IBM 担当者と連携してください。

方法2：API でテスト送信する

Postman などを使い、以下のエンドポイントに POST することでテストデータを送信できます。

POST https://{organization_ID}.messaging.iot.masdomain.com/api/v0002/device/types/{type_ID}/devices/{device_ID}/events/{event_name}

Body には定義した Metric 名をキーとした JSON を指定します（例：{"temperature": 25, "pressure": 101}）。

詳細は IBM Documentation — Sending data from a device を参照してください。

受信を確認する

  1. 対象デバイスタイプの 「デバイス」タブ を開く
  2. 確認したいデバイスを選択する
  3. 「最近のイベント」 セクションでデータの受信履歴を確認する

データが届いていれば、タイムスタンプと値が一覧表示されます。

データの受信が確認できたら、次はダッシュボードを作成して実際に値を表示してみましょう。

Calculated metric（計算済みメトリクス）について

生データに関数を適用してより複雑な値を生成したい場合は、Calculated metric（計算済みメトリクス） を使用します。

Calculated metric でできることの例：

  • 一定期間の平均値・最大値・最小値を計算する
  • しきい値を超えたときに True/False を返すフラグを作成する
  • 複数センサーのデータを組み合わせた複合指標を導出する
Maximo Monitor 9.1 以降では streaming data metrics は利用できません。9.2 環境では、計算済みメトリクスを作成する場合は batch data metric を前提に確認してください。

設定の詳細は IBM Documentation — Creating raw metrics および IBM Documentation — Creating batch or streaming data metrics を参照してください。

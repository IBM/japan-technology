watsonx.data (SaaS) の利用開始

watsonx.data (SaaS) のサービスインスタンスのプロビジョニング
最終更新: 2026/8/6

watsonx.dataのプロビジョン

左上の検索ボックスに "watsonx.data"と入力し、"Catalog Results"の中から"watsonx.data"を選択します。

watsonx.dataのプロビジョン画面が表示されます。有償環境であればEnterpriseプランを、無償環境の場合にはLiteプランを選択します。ここではEnterpriseプランを選択した場合の画面例を示します。

Planの詳細は以下をご参照ください。
https://cloud.ibm.com/docs/watsonxdata?topic=watsonxdata-getting-started_1&locale=ja

LocationやService Nameなどの項目を入力し、ライセンス使用条件に目を通したらチェックボックスをクリックし、"Create"を選択します。下記画面は、以下を選択した場合の例を示します。なお、Service Nameは後から変更することも可能です。
・Location：Tokyo
・Service Name："watsonx.data-snw" (任意の名前に変更が可能)
(その他の項目はデフォルト値のまま)

Createボタンを押下すると、自動的にIBM CloudのResource List画面に戻ります。
watsonx.dataは「Databases」カテゴリに含まれます。エントリーが作成されていることを確認してください。
プロビジョン直後でステータスが「Active」になっていない場合は、下記のように表示されるまでしばらく待機してください。

【重要】未使用インスタンスの自動削除 インスタンス作成後、7日以内にResource Unit(RU)が一切消費されない場合、未使用のインスタンスは削除されます(削除後の再作成は可能です)。インスタンス作成は、次章のクイックスタートを実施できるタイミングで行ってください。

(参考) アカウントスコープのインスタンス

新規に作成されるwatsonx.dataインスタンスは、アカウントスコープで動作します。Enterpriseプランの最大リソースクォータはアカウントあたり256 vCPU / 1024 GBメモリであり、上限の引き上げにはIBMサポートへの連絡が必要です。また、アカウントレベルでメタデータを共有(Metadata scoping at account level)できるため、複数インスタンスのSpark/Prestoエンジンを同一のメタデータに関連付けることが可能です。
参考：Release notes

(参考) CLI / Terraform でのプロビジョニング

UIのほか、IBM Cloud CLIやTerraformでもインスタンスを作成できます。CLIの場合の例(東京リージョン、Enterpriseプラン)：

ibmcloud resource service-instance-create <instance-name> lakehouse lakehouse-enterprise jp-tok -g Default -p '{"datacenter": "ibm:jp-tok:tok","cloud_type": "ibm"}'
  • シドニー(au-syd)・トロント(ca-tor)リージョンでは、plan-idが lakehouse-enterprise-mcsp となる点に注意してください。
  • VPC内からプライベート接続するVPE(Virtual Private Endpoint)対応インスタンスは、us-south / us-east / eu-de / au-syd / ca-torで作成可能です(2026年3月更新のドキュメント時点で、東京リージョンはVPE対応の記載がありません)。
  • Terraformでは公式モジュール(Terraform IBM Modules（英語）)が提供されています。

MAS とは

AppPoint ライセンスの考え方 | IBM Maximo Application Suite オンボーディング

MAS のライセンス体系である AppPoint について理解しましょう。

AppPoint とは

MAS では、AppPoint（アップポイント） と呼ばれる統合ライセンス体系を採用しています。

従来の Maximo 7.6 では、利用するアプリケーションやユーザー数ごとに個別のライセンスを購入する必要がありました。MAS では AppPoint という単一の通貨（ポイント）を購入し、それを各 Function・各ユーザーに割り当てる形に変わっています。

購入した AppPoint は、主に以下の 2 つの用途で消費されます。

  • ユーザーへの割り当て — MAS にアクセスするユーザー 1 人ひとりに AppPoint が消費されます
  • アプリケーションのインストール — 一部の Function（Maximo Visual Inspection など）はインストール時にも AppPoint が必要です

このガイドでは、特に利用開始時に重要なユーザーへの割り当てについて説明します。

ユーザーへの割り当て方式

MAS には Authorized（認定） と Concurrent（同時接続） の 2 つの割り当て方式があります。

方式イメージAppPoint の消費タイミング
Authorized🪑 指定席ユーザー作成時に永続予約。ログイン有無に関わらず消費され続ける
Concurrent🎟️ 自由席ログイン中のみ消費。ログアウトすると AppPoint がプールに返却される

Authorized は特定のユーザーに AppPoint が専用で確保されるため、常にログインが保証されます。
Concurrent は組織全体で AppPoint を共有するため、全ての AppPoint が使用中の場合はログインできません。

Concurrent ユーザーがログインできない場合、他のユーザーがログアウトして AppPoint が返却されるまで待つ必要があります。SLM で定期的に消費状況を確認し、AppPoint が不足しそうな場合は早めに追加購入を検討してください。

ユーザータイプ

AppPoint の消費量は、割り当て方式に加えてユーザータイプによっても異なります。

ユーザータイプは以下の 3 種類です。

ユーザータイプ利用できる Function の範囲主な対象
LimitedMaximo Manage の一部モジュール（最大 3 モジュール）、Monitor など承認者・閲覧者・現場作業者
BaseMaximo Manage フル機能、Maximo Health など一般ユーザー・技術者
PremiumMAS の全アプリケーション管理者・スーパーユーザー・IS/Add-on 利用者

各ユーザータイプの正確な AppPoint 消費量および利用可能な Function の詳細は、IBM 公式ドキュメント を参照してください。

モジュールとは、Maximo Manage 内の業務領域ごとの機能グループです（例：資産、作業指示、在庫など）。Limited ユーザーが選択できる 3 モジュールには制限があります。「計画・スケジューリング」「アプリケーション管理」「管理」「統合」「システム構成」「セキュリティ」は選択できません。

管理者ユーザーについて

MAS の管理者ユーザー（Suite 管理者・アプリケーション管理者）は、Authorized 方式と同様に AppPoint が常時予約されます。そのため、管理者は AppPoint の残量に関わらず常にログインできます。

なお、管理者ユーザーにはアプリケーションの利用権限も付与できるため、管理者兼一般ユーザーとして使う場合でも AppPoint の追加消費は発生しません。

AppPoint の管理

Suite License Manager（SLM）での確認

購入した AppPoint の残量や消費状況は、MAS の管理画面である Suite License Manager（SLM） で確認できます。
SLM の確認方法については、Suite License Manager でライセンス確認 を参照してください。

Compliance Enforcement について

SLM には Compliance Enforcement（コンプライアンス強制） という設定があります。

  • 有効（デフォルト）: AppPoint が不足すると Concurrent ユーザーのログインがブロックされます
  • 無効: AppPoint が不足していてもログインはブロックされません（警告のみ）

Compliance Enforcement を無効にしている場合でも、ライセンス違反の状態が続くことになります。定期的に SLM で消費状況を確認することを推奨します。

AppPoint の追加購入には一定のリードタイムが必要です。残量が少なくなってきたら、担当の IBM 営業またはパートナーにご相談ください。

よくある質問

Q. 自分のアカウントが Concurrent か Authorized かを確認するには？

A. ご利用の契約形態によって決まっており、個別に変更することはできません。ご自身のアカウントがどちらの方式かは、MAS 管理者にご確認ください。

Q. 同じユーザーが複数の Function を使う場合、AppPoint は Function の数だけかかりますか？

A. いいえ。同一ユーザーが複数の Function を利用する場合でも、そのユーザーのユーザータイプに応じた AppPoint を 1 回消費するだけです。AppPoint は Function ごとではなく、ユーザーごとに消費されます。

Q. Authorized ユーザーは AppPoint が超過していてもログインできますか？

A. はい。Authorized ユーザーはユーザー作成時点で AppPoint が永続的に予約されるため、AppPoint の残量に関わらず常にログインできます。ただし、Authorized ユーザーを追加作成しようとした際に AppPoint が不足している場合は、新規ユーザーの追加ができません。

Q. Concurrent と Authorized はどちらを選ぶべきですか？

A. 利用者の使用パターンによります。常時ログインが必要なユーザー（管理者・日常的に使う担当者）には Authorized が適しています。一方、利用頻度が低いユーザーが多い場合は Concurrent の方が AppPoint を効率よく使えます。最適な組み合わせについては、担当の IBM 営業またはパートナーにご相談ください。

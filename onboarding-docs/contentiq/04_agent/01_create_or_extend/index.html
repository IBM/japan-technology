エージェント

wxO エージェントへのナレッジ付与

既存エージェントの拡張と新規エージェントの作成
最終更新: 2026/9/18

2 つの方式

ContentIQ は wxO のエージェント・オーケストレーション層と連携し、取り込んだナレッジを wxO エージェントに付与します。

方式選択タイミング向いているケース
Use Existing Agent各取り込みフローの Agent Type 選択時wxO 側でエージェントの振る舞い（instructions、ツール、コラボレーター）を先に設計している場合。本ガイドの推奨
Create New Agent同上ナレッジ Q&A のみのエージェントを素早く立ち上げる場合。Step 3 で Agent Name（必須）と Description（任意）を入力すると、取り込み完了時に wxO エージェントが作成されます。指示は後から wxO 側で設定します

推奨手順（既存エージェントの拡張）

  1. wxO の Agent Builder でエージェントを作成します（Agent Builder の使い方）。
  2. ContentIQ の取り込みウィザード（Step 2）で Use Existing Agent を選択し、Step 3 の一覧から該当エージェントを選びます。一覧は検索ボックスで絞り込めます。

  1. 取り込み完了後、wxO 側でツールが追加されていることを確認します（次節）。同じエージェントに追加取り込みした場合は、既存のツールが更新されます（ツール名は変わりません）。
  2. エージェントの 指示 に、ContentIQ のツールを使う条件を明記します（後述）。wxO エージェントはツールを使うかどうかを指示と質問内容から判断するため、確実に使わせるには指示での明記が必要です。

wxO 側での確認

ContentIQ は、取り込みパイプラインの最終段階「Upload wxO Tool」で、対象エージェントに ツールを追加します（Knowledge には何も追加されません）。以下の手順で確認します。

  1. wxO の Agent Builder で対象エージェントを開きます。
  2. ツール タブを開きます。symplisticai_tool_<エージェント名のスラッグ>_a_<12 桁の英数字> という名前のツールが追加されています（例: エージェント名が RAGエージェント(ContentIQ) なら symplisticai_tool_rag_contentiq_a_…）。
    • タイプ: コード化（Python ツール）
    • 説明: 外部エンドポイントを呼び出してセマンティック RAG の結果と構造化データを取得し、両方の結果を結合して返す
    • コネクター: 0 件
    • パラメーター（Locked schema。説明文のみ編集可）: 入力は query（必須）、original_question、request_origin、source_channel、thread_id、turn_id の 6 件、出力は any 型 1 件（RAG と構造化データの結合結果）。API キーや URL に相当するパラメーターはなく、接続先と認証情報はツール定義内に保持されます。ツール定義には取り込みを実行した ContentIQ ユーザーの情報が含まれ、その情報で ContentIQ の文書情報を検索します。このため、取り込みは個人アカウントではなくサービス用アカウントで行うことを推奨します（セキュリティと RBAC 参照）

  1. ツール・カードの 詳細の編集 を開くと、名前・説明・パラメーター・コネクターを確認できます。

  1. 知識 タブが空のままであることを確認します。ContentIQ のナレッジは wxO の Knowledge ではなくツール経由で参照されます。

エージェントの指示（重要）

ツールが追加されただけでは、エージェントは質問のたびにツールを使うとは限りません。wxO エージェントはツールを使うかどうかを指示と質問内容から判断するため、指示が空の状態ではツールを使わずに回答する場合があります（実機検証で確認）。これは ContentIQ 固有ではなく、wxO のツール付きエージェント全般に共通する設計上の注意点です。

動作 タブの 指示 に、ツールを使う条件と根拠制御を明記してください。例:

あなたは社内規程に関する質問に答えるアシスタントです。
ユーザーからの質問には、必ず最初に symplisticai_tool_rag_contentiq ツールを呼び出して関連する規程を検索し、その結果のみに基づいて回答してください。
ツールの結果に該当する情報がない場合は「規程に該当する記載を確認できません」と回答し、一般知識で補わないでください。
回答には根拠となる条文や見出しを引用してください。

指示は ContentIQ 側の Agent List → エージェント詳細 → Agent Behaviour にも表示され、そこから編集して Update すると wxO 側の指示に即時反映されます（実機確認済み）。wxO と ContentIQ のどちらからでも編集できるため、上書き事故を避けるには指示の管理場所を一方（通常は wxO の Agent Builder）に決めておくことを推奨します。

ツール定義（説明文を含む）は ContentIQ が管理しており、同じエージェントに再取り込みを行うと ContentIQ 側の内容に更新されます（実機確認済み。ツール名・ツール数は変わらず、同じツールが更新される）。エージェントの指示は再取り込みの影響を受けません（実機確認済み）。そのため、ツールを使う条件（トリガー条件）はツール説明文ではなく、エージェントの指示に書いてください。

動作確認

  1. エージェント画面右側の ドラフト・プレビュー で、取り込んだ文書に関する質問を日本語で行います。
  2. 回答が取り込んだ文書の内容に基づいており、根拠（条文番号や見出し）が引用されていることを確認します。

  1. 回答の 理由の表示 から デバッグ ビューを開き、実行タイムラインに Tool: symplisticai_tool_rag_contentiq_… のツール呼び出しステップ（POST /api/v1/runtime/tools/:toolId/run → HTTP POST → POST /execute）が含まれていることを確認します。

タイムラインが Agent Reasoning → WatsonxChatModel.chat → Answer のみでツール呼び出しがない場合、エージェントはツールを使っていません。指示を見直してください。

参考（実機検証 2026-09-09）
指示が空の状態では、就業規則の質問に対してツールを使わずに回答しました（6 ステップ、約 7 秒）。指示を明記した後は、ツールを呼び出して条文番号を引用した回答になりました（16 ステップ、約 33 秒。うちツール呼び出し約 13 秒）。
既定モデル（groq/openai/gpt-oss-120b）でも、指示でツール呼び出しを明記すればツールが使われることを確認しています（ユースケース例 の Step 2）。
なお、この検証では指示の追加と同時にモデルも変更しています（GPT-OSS 120B → watsonx Orchestrate Frontier）。ツールを呼び出すかどうかの判断はモデルによって異なる場合があるため、期待どおり動作しない場合はモデルの変更も試してください。

回答の根拠制御

ContentIQ は wxO エージェントに ツールとして付与されるため、wxO の Knowledge（会話型検索）向けの設定（検索信頼度しきい値、応答信頼度しきい値、引用の表示設定）は ContentIQ の検索結果には適用されません。根拠制御は以下の手段で行います。

手段内容
エージェントの指示ツール呼び出しを必須化し、「ツールの結果のみに基づいて回答する」「該当がなければその旨を答える」「根拠を引用する」を明記する（前節の例）
ツールの説明文「詳細の編集」から、どのような質問でこのツールを使うか（トリガー条件）を追記する
ContentIQ 側ツールは取り込み済みコンテンツから検索した結果を返します。検索対象を絞りたい場合は、ソース単位のアクセス・ロール（Content Management の Manage Access）や、エージェントごとの取り込み範囲で制御します

出典の表示は経路によって異なります。

  • ContentIQ の Chat Playground / Headless API: 回答に引用マーカーと Sources（文書単位）が付きます
  • wxO の Preview / チャネル: LLM がツールの結果から回答を構成するため、出典カードは表示されません。条文番号などの根拠は、指示で引用を求めることで回答本文に含めさせます（実機確認済み）

wxO 標準のナレッジ（ファイル・アップロードや外部ベクトル DB）を併用する場合は、そちらに対して IBM Docs: Conversational search（英語） の設定が利用できます。

マルチエージェント構成

ContentIQ はドメイン別の複数エージェントへのルーティングと、ContentIQ エージェントから wxO ワークフローへのハンドオフをサポートします。wxO 側のマルチエージェント設定は マルチ・エージェント・オーケストレーション機能の使い方 を参照してください。

エージェント ID の確認

Headless API で必要となるエージェント ID（wxO Agent ID）は、以下で取得できます。

方法備考
wxO の Agent Builder でエージェントを開いたときの URL 末尾の UUID最も確実
Headless API の取り込み応答 JSON の agent_id既に取り込み済みの場合
ContentIQ の取り込みステータスページ（Document Upload Status）の見出し下の AGENT ID（Copy ボタン付き）実機確認済み（文書アップロードの場合）
ContentIQ の Usage Analytics でエージェントを選び、AGENT カードのエージェント名の下実機確認済み
ContentIQ の Agent List でエージェントを開いた詳細ページ（Agent ID、Agent Model、Author、Last Updated）実機確認済み

Agent List の詳細ページには Agent Configuration として以下の 2 項目があります。

  • SQL Query Instructions — 構造化データ（CSV / Excel 等）に対するクエリの解釈方法を指示します（最大 5,000 文字）。文書のみを取り込んでいる場合は空のままで構いません
  • Agent Behaviour — wxO エージェントの「指示」が表示され、ContentIQ 側から編集して Update できます（最大 25,000 文字）。Update した内容は wxO 側の指示に即時反映されます（実機確認済み）

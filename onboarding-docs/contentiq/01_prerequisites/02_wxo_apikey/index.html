wxO API キーの取得

ContentIQ に登録する watsonx Orchestrate の API キーと API URL（IBM Cloud / AWS）
最終更新: 2026/9/18

概要

ContentIQ は wxO の API キーと API URL（サービス・インスタンス URL）を使って wxO と接続します。wxO SaaS は IBM Cloud と AWS の両方で提供されており、サービス・インスタンス URL の取得手順は共通ですが、API キーの生成手順と URL の形式が異なります。利用しているインスタンスの提供基盤に合わせて読み進めてください。

いずれの基盤でも、IBM Docs の Getting credentials for your environments（英語） に IBM Cloud、AWS、オンプレミスそれぞれの手順が記載されています。API キーの作成から認証トークンの生成、エンドポイントの呼び出しまでの流れは IBM Docs: API の開始（目次は日本語、本文は英語）も参考になります。

共通の手順（サービス・インスタンス URL の取得）

  1. wxO にログインします。
  2. 画面右上のユーザー・アイコンから 設定 を開きます。
  3. APIの詳細 タブを開きます。
  4. サービス・インスタンスURL を控えます。この値が、ContentIQ の Settings で登録する Orchestrate API URL に相当します。

注意
画面は IBM Cloud 上のトライアル環境の例です。表示言語が英語の場合、各項目は Settings、API details、Generate API key、Service instance URL と表示されます。

API キーの生成: IBM Cloud の場合

  1. 上記の APIの詳細 タブで API キーの生成 をクリックします。
  2. IBM Cloud の IAM（Identity and Access Management）画面に移動します。作成 をクリックし、API キーの名前と説明を入力して作成します。
  3. 表示された API キーをコピーし、安全な場所に保管します。

注意
IBM Cloud のリソース・リストから取得できる資格情報は使用しないでください。必ず wxO の設定画面から IAM に移動して作成した API キーを使用します（IBM Docs の注記）。
API キーは作成時にのみ表示されます。

API キーの生成: AWS の場合

  1. 上記の APIの詳細 タブで API キーの生成 をクリックします。
  2. 画面に表示された API キーをコピーし、安全な場所に保管します。

注意
AWS 環境の API キーは後から参照・編集・削除できません。生成した時点で必ず保管してください。
1 環境あたり 10 個までの制限があります。上限に達した場合は IBM サポートに問い合わせます（IBM Docs の注記）。

API URL の形式

サービス・インスタンス URL の形式は提供基盤によって異なります。リージョンやインスタンス ID を自分で組み立てる必要はなく、上記の共通の手順で APIの詳細 タブからコピーした値をそのまま ContentIQ の Settings に登録します。形式は、コピーした URL がどちらの基盤のものかを確認する際の参考です。

提供基盤形式例
IBM Cloudhttps://api.<リージョン>.watson-orchestrate.cloud.ibm.com/instances/<インスタンスID>リージョンはインスタンスの作成先
AWShttps://api.<リージョン・コード>.watson-orchestrate.ibm.com/instances/<テナントID>リージョン・コードは AWS のリージョン（IBM Docs の記載）

ホスト名の watson-orchestrate.cloud.ibm.com（IBM Cloud）と watson-orchestrate.ibm.com（AWS）の違いで、どちらの基盤かを判別できます。形式の詳細は IBM Docs: Getting the API endpoint（英語） を参照してください。

ContentIQ から利用する際の権限

ContentIQ は API キーを使って以下を行います。

  • 既存エージェントの一覧取得と検索ツールの登録
  • 新規エージェントの作成（「Create New Agent」を選択した場合）
  • エージェントの指示の読み取りと更新（Agent Behaviour）

API キーに紐づくユーザーには、これらの操作に必要な wxO 側の権限が必要です。

規約ナレッジによる文書チェック・エージェントの構築方法

規約を ContentIQ に取り込み、wxO のフローで文書の規約適合を一次チェックする構成の実装例
最終更新: 2026/9/15

概要

業務規約（記載ルール、用語規則、整合性ルール等）を ContentIQ のナレッジとして取り込み、watsonx Orchestrate（wxO）のフローで入力文書の規約適合を一次チェックし、担当者が最終確認を行う構成を説明します。

熟練者にしかできなかったチェックの一次判定を AI が行い、熟練者は根拠付きの指摘を確認・承認する役割にシフトすることを想定しています。

本ページのコード（エージェント定義、ツール、フロー）は watsonx Orchestrate ADK 2.x で実行確認済みです（2026 年 9 月）。ContentIQ 側の手順は自己ホスト版 v1.4.3 の検証環境で確認しています。ADK のバージョンによって API が変わる場合があるため、最新ドキュメントと合わせて確認してください。

構成

入力文書（テキスト）
   │
   ▼
wxO フロー
   ├─ ① 構造化抽出ツール（Python）       文書 → 項目ごとの JSON
   ├─ ② 決定論的チェックツール（Python）  必須項目・書式・用語辞書 → 指摘 A
   ├─ ③ 規約照合エージェント（agentic）   ContentIQ ナレッジで整合性を判定 → 指摘 B（条項引用付き）
   ├─ ④ 統合ツール（Python）             A + B → 指摘レポート（重大度付き）
   └─ ⑤ 担当者レビュー（2ステップ）
        ├─ ⑤-a 一次チェック結果の表示
        └─ ⑤-b 承認 / 差戻しフォーム

規約を「決定論的に判定できるもの」と「解釈が必要なもの」に分けています。前者はツールで確実に検出し、後者のみ RAG + LLM（ContentIQ ナレッジ + 規約照合エージェント）で判定します。これにより、単純なルール違反は毎回必ず検出され、複雑な整合性判断はエージェントが条項引用付きで判定します。

規約の類型例判定
記載必須項目項目の有無・必須値② ツール
書式単位・略語・表記揺れ② ツール
用語・分類標準用語・分類基準への準拠② 辞書照合 + ③ RAG
整合性項目間の矛盾・コメントの妥当性③ RAG + LLM

前提条件

  • watsonx Orchestrate インスタンスへのアクセス権があること
  • ADK 2.x がインストールされていること（orchestrate --version で確認）
  • orchestrate env activate <環境名> で対象環境をアクティブにしていること

ADK のセットアップは ADK の使い方 を参照してください。

Step 1: 規約文書の準備

規約文書を収集・整形する

以下の文書を収集します。

  • 業務規約・基準・記載ガイドライン
  • 過去の指摘事例（匿名化済み）
  • 用語集

条項単位で見出しを付け、テキスト層のある PDF または DOCX に整えます。スキャン文書は OCR 処理します。

決定論的判定用のルールファイルを準備する

必須項目・書式・禁止用語のような単純な判定条件は、ツール（②）でルールベースに検出します。判定条件は規約担当者と合意するために、まず以下のような整理表（JSON）にまとめます。実装（Step 4）ではフローエンジン上で外部ファイルを参照できないため、この内容をツール内に直接記述します。

// rules/required_fields.json  ─ 必須項目と根拠条項
{ "sample_id": "第3条", "test_item": "第3条", "measured_value": "第3条", "judgement": "第3条", "author": "第3条", "approver": "第3条" }

// rules/format_rules.json  ─ 書式ルールと根拠条項
{ "clause": "第4条", "created_date": "^\\d{4}-\\d{2}-\\d{2}$" }

// rules/forbidden_terms.json  ─ 禁止用語と根拠条項
{ "clause": "第7条", "terms": ["OK", "NG", "check", "temp"] }

// rules/term_dictionary.json  ─ 標準用語マッピング
{ "clause": "第6条", "mapping": { "陽性": "陽性", "＋": "陽性", "−": "陰性" } }

Step 2: 規約照合エージェントの作成（wxO）

ContentIQ へのドキュメント取り込み時に、連携するエージェントを指定する必要があります。先にエージェントを作成します。

エージェント定義ファイルを作成する

# agents/rule_compliance_agent.yaml
spec_version: v1
kind: native
name: rule_compliance_agent
display_name: 規約照合エージェント
description: |
  業務規約のナレッジベースを参照し、入力文書が規約に適合しているかを照合するエージェント。
  RAG 検索で根拠条項を引用したうえで記載漏れ・書式違反・整合性の問題を JSON 形式で返す。

llm: groq/openai/gpt-oss-120b
style: react_core
hide_reasoning: false
memory_enabled: false

instructions: |
  あなたは業務規約の照合を行うアシスタントです。
  入力された文書の内容が規約に適合しているかを判定してください。

  ## 判定の手順

  1. 必ず最初に、名前が symplisticai_tool_ で始まるツールを呼び出して規約ナレッジを検索し、その結果のみに基づいて判定する。ツールを呼ばずに一般知識で回答しない。
  2. 以下の観点で文書を照合する。
     - 規約が定める必須記載項目の記載状況
     - 書式・用語規則への準拠
     - 項目間の整合性（矛盾・コメントの妥当性）
  3. 根拠が見つからない場合は「規約上の根拠を確認できません」とし、推測で判定しない。

  ## 出力形式

  必ず以下の JSON 配列形式で出力すること。指摘がない場合は空配列 [] を返すこと。

  [
    {
      "issue": "指摘内容の概要",
      "field": "問題が検出されたフィールド名",
      "clause": "根拠条項（例: 第3条・第7条）",
      "severity": "high または medium または low",
      "reason": "判定の根拠（条項の該当箇所を引用）"
    }
  ]

guidelines:
  - condition: "必須記載項目が欠落している"
    action: "根拠条項を引用して high で指摘する"
  - condition: "書式または用語規則に違反している"
    action: "根拠条項を引用して medium または low で指摘する"
  - condition: "項目間に矛盾または整合性の問題がある"
    action: "根拠条項を引用して重大度に応じた severity で指摘する"

# ContentIQ でナレッジを投入すると、symplisticai_tool_ で始まるツールが
# このエージェントに自動的に追加される。手動での編集・再インポートは不要。
knowledge_base: []
tools: []
collaborators: []

tools はこの時点では空のままにします。ContentIQ でナレッジを取り込むと、ContentIQ ツールが自動的に追加されます。ツールを使うかどうかはエージェントの判断に委ねられるため、instructions でツール呼び出しを必須化しています（上記のモデル groq/openai/gpt-oss-120b で、この指示によりツールが呼び出されることを確認済み）。

エージェントをインポートする

orchestrate agents import -f agents/rule_compliance_agent.yaml

インポート結果を確認する

orchestrate agents list

rule_compliance_agent が登録されていることを確認します。

Step 3: 規約文書を ContentIQ に取り込む

規約文書をアップロードする

ContentIQ の Connections → Document Upload で Step 1 の規約文書をアップロードします。

エージェントを紐付ける

Agent Type で Use Existing Agent を選び、Step 2 でインポートした rule_compliance_agent を選択します。

取り込み結果を確認する

Ingest Analytics で成功率と埋め込みカバレッジを確認します。

Chat Playground で動作確認する

「〜は規約に適合していますか」のように判定を求める形で質問します。Step 2 の instructions どおり、判定結果が JSON で返り、根拠条項の引用が続いて表示されることを確認します。

「〜について教えて」のような説明要求では散文で回答されます。動作確認では判定を求める質問形式に統一してください。

条項の境界がずれている場合は Content Management でチャンクを編集します（チャンク編集とバージョン履歴は v1.4.4 で追加された機能です。SaaS 版は v1.4.4 のため利用できますが、本ページの検証環境である自己ホスト版 v1.4.3 では確認していません。v1.4.3 では該当ソースを削除し、文書の見出し構造を整えて再取り込みしてください）。

Step 4: ツールの作成・インポート（wxO）

本 Step と Step 5 のコードは watsonx Orchestrate ADK 公式ドキュメント（英語） の API に準拠した設計例です。ADK のバージョンによって API が変わる場合があるため、最新ドキュメントと合わせて確認してください。

wxO ADK で以下の 3 つの Python ツールを作成します。

ファイル役割
tools/extract_report.py① 文書テキストを項目ごとの JSON に分解する
tools/check_deterministic.py② 必須項目・書式（日付）・禁止用語・用語辞書をルールベースで照合し、指摘リストとサマリーを返す
tools/build_summary.py④ ②と③の指摘を統合した担当者向けサマリーを生成する

① 構造化抽出ツール（extract_report.py）

文書テキストを受け取り、「項目名: 値」形式の行を正規表現で抽出して、後続ツールが利用できる JSON 構造を返します。様式が固定でない場合は正規表現部分を wxO のプロンプト・ノードに置き換えます。

# tools/extract_report.py
import re
from typing import Optional
from pydantic import BaseModel, Field
from ibm_watsonx_orchestrate.agent_builder.tools import tool


class ReportFields(BaseModel):
    created_date:   Optional[str] = Field(None, description="作成日")
    sample_id:      Optional[str] = Field(None, description="検体 ID")
    test_item:      Optional[str] = Field(None, description="検査項目")
    measured_value: Optional[str] = Field(None, description="測定値")
    judgement:      Optional[str] = Field(None, description="判定")
    author:         Optional[str] = Field(None, description="担当者")
    approver:       Optional[str] = Field(None, description="責任者")
    comment:        Optional[str] = Field(None, description="コメント")
    raw_text:       str           = Field(description="元の報告書テキスト")


# 値が空の行（例: 「担当者:」のみ）は未記入として None にする
_PATTERNS = {
    "created_date":   r"作成日\s*[:：][ \t]*(\S.*)",
    "sample_id":      r"検体\s*ID\s*[:：][ \t]*(\S.*)",
    "test_item":      r"検査項目\s*[:：][ \t]*(\S.*)",
    "measured_value": r"測定値\s*[:：][ \t]*(\S.*)",
    "judgement":      r"判定\s*[:：][ \t]*(\S.*)",
    "author":         r"担当者\s*[:：][ \t]*(\S.*)",
    "approver":       r"責任者\s*[:：][ \t]*(\S.*)",
    "comment":        r"コメント\s*[:：][ \t]*(\S.*)",
}


@tool(
    name="extract_report",
    display_name="文書構造化抽出",
    description="報告書テキストを項目ごとに分解し、後続チェックツールが利用できる JSON 構造を返します。",
)
def extract_report(report_text: str) -> ReportFields:
    """報告書テキストを項目ごとに分解します。

    Args:
        report_text: 報告書の全文テキスト

    Returns:
        ReportFields: 項目ごとに分解したフィールド
    """
    fields: dict = {"raw_text": report_text}
    for key, pattern in _PATTERNS.items():
        m = re.search(pattern, report_text)
        fields[key] = m.group(1).strip() if m else None
    return ReportFields(**fields)

② 決定論的チェックツール（check_deterministic.py）

必須項目・書式（作成日）・禁止用語・用語辞書との照合を行い、指摘リストとサマリーを返します。判定条件はツール内にインライン定義されており、ルールを変更する場合はファイルを再インポートします。

フローエンジン上では外部ファイル参照（Path(__file__) など）が使用できないため、ルール定義はツール内に直接記述しています。
# tools/check_deterministic.py
import re
from typing import List
from pydantic import BaseModel, Field
from ibm_watsonx_orchestrate.agent_builder.tools import tool


# ── ルール定義（インライン）────────────────────────────────────────────────
# rules/required_fields.json に相当
REQUIRED_FIELDS: dict[str, str] = {
    "sample_id":      "第3条",
    "test_item":      "第3条",
    "measured_value": "第3条",
    "judgement":      "第3条",
    "author":         "第3条",
    "approver":       "第3条",
}

# rules/format_rules.json に相当（作成日は YYYY-MM-DD 形式）
FORMAT_CLAUSE = "第4条"
DATE_PATTERN = re.compile(r"^\d{4}-\d{2}-\d{2}$")

# rules/forbidden_terms.json に相当
FORBIDDEN_CLAUSE = "第7条"
FORBIDDEN_TERMS: list[str] = ["OK", "NG", "check", "temp"]

# rules/term_dictionary.json に相当
TERM_CLAUSE = "第6条"
TERM_MAPPING: dict[str, str] = {
    "陽性": "陽性", "＋": "陽性", "+": "陽性",
    "陰性": "陰性", "−": "陰性", "-": "陰性",
    "要再検": "要再検", "正常": "正常", "異常": "異常",
    "適合": "適合", "不適合": "不適合",
}


# ── データモデル ──────────────────────────────────────────────────────────
class Finding(BaseModel):
    issue:    str = Field(..., description="指摘内容")
    clause:   str = Field(..., description="根拠条項")
    severity: str = Field(..., description="high / medium / low")
    reason:   str = Field(..., description="理由")
    source:   str = Field(default="deterministic", description="指摘の発生源")


class CheckResult(BaseModel):
    """決定論的チェック結果（サマリー付き）"""
    findings:   List[Finding] = Field(default_factory=list, description="指摘リスト")
    high_count: int           = Field(default=0, description="重大度 high の件数")
    total:      int           = Field(default=0, description="指摘の総数")
    summary:    str           = Field(default="", description="担当者向けサマリーテキスト")
    raw_text:   str           = Field(default="", description="元テキスト（後続エージェントが参照）")


def _build_summary(findings: List[Finding]) -> str:
    high   = [f for f in findings if f.severity == "high"]
    medium = [f for f in findings if f.severity == "medium"]
    low    = [f for f in findings if f.severity == "low"]
    lines = [
        f"指摘総数: {len(findings)} 件（high: {len(high)}、medium: {len(medium)}、low: {len(low)}）",
        "",
    ]
    if high:
        lines.append("【要対応】high 指摘を優先確認してください。")
        for f in high:
            lines.append(f"  - {f.issue}（{f.clause}）")
        lines.append("")
    if medium:
        lines.append("【確認推奨】medium 指摘: 書式または用語の問題があります。")
        for f in medium:
            lines.append(f"  - {f.issue}（{f.clause}）")
        lines.append("")
    if low:
        lines.append("【参考】low 指摘: 用語の統一など。")
        for f in low:
            lines.append(f"  - {f.issue}（{f.clause}）")
    return "\n".join(lines)


@tool(
    name="check_deterministic",
    display_name="決定論的ルールチェック",
    description="必須項目・禁止用語・用語辞書をルールベースで照合し、指摘リストとサマリーを返します。",
)
def check_deterministic(
    created_date:   str | None,
    sample_id:      str | None,
    test_item:      str | None,
    measured_value: str | None,
    judgement:      str | None,
    author:         str | None,
    approver:       str | None,
    comment:        str | None,
    raw_text:       str,
) -> CheckResult:
    """報告書フィールドを必須項目・書式・禁止用語・用語辞書と照合して指摘を返します。

    Args:
        created_date:   作成日（① の出力）
        sample_id:      検体・対象物 ID（① の出力）
        test_item:      検査・確認項目名（① の出力）
        measured_value: 測定値・確認結果（① の出力）
        judgement:      判定結果（① の出力）
        author:         担当者（① の出力）
        approver:       責任者（① の出力）
        comment:        コメント（① の出力、未使用）
        raw_text:       元の報告書テキスト全文

    Returns:
        CheckResult: 指摘リスト・カウント・サマリー・元テキスト
    """
    fields = {
        "sample_id":      sample_id,
        "test_item":      test_item,
        "measured_value": measured_value,
        "judgement":      judgement,
        "author":         author,
        "approver":       approver,
    }
    findings: List[Finding] = []

    # 必須項目チェック
    for field_name, clause in REQUIRED_FIELDS.items():
        if not fields.get(field_name):
            findings.append(Finding(
                issue=f"必須項目「{field_name}」が記載されていません",
                clause=clause, severity="high",
                reason="必須項目の欠落",
            ))

    # 書式チェック（作成日）
    if created_date and not DATE_PATTERN.match(created_date.strip()):
        findings.append(Finding(
            issue=f"作成日「{created_date}」が YYYY-MM-DD 形式ではありません",
            clause=FORMAT_CLAUSE, severity="medium",
            reason="日付の書式規則に反する",
        ))

    # 禁止用語チェック
    for term in FORBIDDEN_TERMS:
        if term in raw_text:
            findings.append(Finding(
                issue=f"禁止用語「{term}」が使用されています",
                clause=FORBIDDEN_CLAUSE, severity="medium",
                reason="規約で定める用語規則に反する",
            ))

    # 用語辞書チェック
    if judgement and judgement not in TERM_MAPPING.values():
        canonical = TERM_MAPPING.get(judgement)
        findings.append(Finding(
            issue=f"判定「{judgement}」は標準用語ではありません"
                  + (f"（標準: {canonical}）" if canonical else "（第6条の標準用語一覧を参照）"),
            clause=TERM_CLAUSE, severity="low",
            reason="標準用語への統一が必要",
        ))

    high_count = sum(1 for f in findings if f.severity == "high")
    return CheckResult(
        findings=findings,
        high_count=high_count,
        total=len(findings),
        summary=_build_summary(findings),
        raw_text=raw_text or "",
    )

④ 統合ツール（build_summary.py）

②（決定論的チェック）のサマリー文字列と③（規約照合エージェント）の指摘 JSON を受け取り、担当者向けの統合サマリーテキストを生成します。

フローエンジンの script ノードでは import 文が使用できないため、JSON パースが必要なこのステップは Python ツールとして実装しています。
# tools/build_summary.py
import json
from typing import List
from pydantic import BaseModel, Field
from ibm_watsonx_orchestrate.agent_builder.tools import tool


class SummaryResult(BaseModel):
    """統合サマリー結果"""
    final_summary: str = Field(default="", description="担当者向け統合サマリーテキスト")
    total:         int = Field(default=0,   description="全指摘件数（決定論的 + エージェント）")


@tool(
    name="build_summary",
    display_name="サマリー統合",
    description=(
        "決定論的チェックのサマリーと規約照合エージェントの指摘 JSON を受け取り、"
        "担当者向けの統合サマリーテキストを返します。"
    ),
)
def build_summary(
    det_summary:         str,
    det_total:           int,
    agent_findings_json: str,
) -> SummaryResult:
    """決定論的チェック結果とエージェント指摘を統合してサマリーを生成します。

    Args:
        det_summary:         check_deterministic の summary フィールド
        det_total:           check_deterministic の total フィールド
        agent_findings_json: 規約照合エージェントの出力 JSON 文字列（配列または単一オブジェクト）

    Returns:
        SummaryResult: 統合サマリーテキストと全指摘件数
    """
    try:
        agent_items = json.loads(agent_findings_json) if agent_findings_json else []
        if isinstance(agent_items, dict):
            agent_items = [agent_items]
        if not isinstance(agent_items, list):
            agent_items = []
    except Exception:
        agent_items = []

    agent_high   = sum(1 for f in agent_items if f.get("severity") == "high")
    agent_medium = sum(1 for f in agent_items if f.get("severity") == "medium")
    agent_low    = sum(1 for f in agent_items if f.get("severity") == "low")

    lines: List[str] = [det_summary or "（決定論的チェック結果なし）"]

    if agent_items:
        lines.append("")
        lines.append(
            f"【規約照合エージェントの追加指摘: {len(agent_items)} 件"
            f"（high: {agent_high}、medium: {agent_medium}、low: {agent_low}）】"
        )
        for item in agent_items:
            clause = f"（{item.get('clause', '')}）" if item.get("clause") else ""
            sev    = item.get("severity", "?")
            issue  = item.get("issue", "（内容不明）")
            lines.append(f"  - [{sev}] {issue}{clause}")

    return SummaryResult(
        final_summary="\n".join(lines),
        total=det_total + len(agent_items),
    )

Step 5: フローの作成・インポート（wxO）

wxO のフロー（Agentic Workflow）で ①→②→③→④ を直列に実行し、最後に担当者のレビューステップ（⑤）へ渡します。⑤ は 2 ステップで構成されており、まず一次チェック結果のサマリーが表示され、続いて担当者が承認または差戻しを選択するフォームが現れます。

フロー定義ファイルを作成する

# flows/rule_check_flow.py
from pydantic import BaseModel, Field
from ibm_watsonx_orchestrate.flow_builder.flows import Flow, flow, START, END
from ibm_watsonx_orchestrate.flow_builder.types import UserFieldKind, Assignment
from ibm_watsonx_orchestrate.flow_builder.data_map import DataMap

from tools.extract_report import extract_report
from tools.check_deterministic import check_deterministic
from tools.build_summary import build_summary


# ── スキーマ定義 ──────────────────────────────────────────────────────────

class FlowInput(BaseModel):
    report_text: str = Field(..., description="チェック対象の報告書テキスト全文")


class AgentInput(BaseModel):
    report_text: str = Field(..., description="チェック対象の報告書テキスト全文")


class AgentOutput(BaseModel):
    agent_findings_json: str = Field(
        default="[]",
        description="エージェントが検出した指摘の JSON 文字列 [{issue, clause, severity, reason}, ...]",
    )


class FlowOutput(BaseModel):
    check_summary:   str = Field(default="", description="一次チェック結果サマリー")
    review_decision: str = Field(default="", description="approved / rejected")
    review_comment:  str = Field(default="", description="差戻し理由など")


# ── フロー定義 ────────────────────────────────────────────────────────────

@flow(
    name="rule_check_flow",
    display_name="規約適合チェックフロー",
    description=(
        "報告書テキストを決定論的チェック → ContentIQ 規約照合エージェント → "
        "サマリー統合 → 担当者レビューの順に実行します。"
    ),
    input_schema=FlowInput,
    output_schema=FlowOutput,
    suppress_agent_summarization=True,
)
def build_rule_check_flow(aflow: Flow = None) -> Flow:

    # ① 構造化抽出ノード
    extract_node = aflow.tool(
        extract_report,
        name="extract_report",
        display_name="① 文書構造化抽出",
    )
    extract_node.map_input(
        input_variable="report_text",
        expression="flow.input.report_text",
    )

    # ② 決定論的チェックノード
    det_node = aflow.tool(
        check_deterministic,
        name="check_deterministic",
        display_name="② 決定論的ルールチェック",
    )
    det_node.map_input(input_variable="created_date",   expression="flow.extract_report.output.created_date",   default_value="")
    det_node.map_input(input_variable="sample_id",      expression="flow.extract_report.output.sample_id",      default_value="")
    det_node.map_input(input_variable="test_item",      expression="flow.extract_report.output.test_item",      default_value="")
    det_node.map_input(input_variable="measured_value", expression="flow.extract_report.output.measured_value", default_value="")
    det_node.map_input(input_variable="judgement",      expression="flow.extract_report.output.judgement",      default_value="")
    det_node.map_input(input_variable="author",         expression="flow.extract_report.output.author",         default_value="")
    det_node.map_input(input_variable="approver",       expression="flow.extract_report.output.approver",       default_value="")
    det_node.map_input(input_variable="comment",        expression="flow.extract_report.output.comment",        default_value="")
    det_node.map_input(input_variable="raw_text",       expression="flow.extract_report.output.raw_text",       default_value="")

    # ③ 規約照合エージェントノード（ContentIQ ナレッジ連携）
    agent_node = aflow.agent(
        name="rule_rag_check",
        agent="rule_compliance_agent",
        display_name="③ ContentIQ 規約照合",
        message=(
            "以下の報告書を読み、規約ナレッジベースを参照して内容を照合してください。"
            "記載漏れ・用語の不備・整合性の問題を確認し、"
            "出力は JSON 形式（配列）で、各要素に issue・clause・severity・reason を含めてください。\n\n"
            "報告書テキスト:\n{flow.check_deterministic.output.raw_text}"
        ),
        input_schema=AgentInput,
        output_schema=AgentOutput,
    )
    agent_node.map_input(
        input_variable="report_text",
        expression="flow.check_deterministic.output.raw_text",
        default_value="",
    )

    # ④ サマリー統合ノード（決定論的チェック結果 + エージェント指摘を合算）
    summary_node = aflow.tool(
        build_summary,
        name="build_summary",
        display_name="④ サマリー統合",
    )
    summary_node.map_input(
        input_variable="det_summary",
        expression="flow.check_deterministic.output.summary",
        default_value="",
    )
    summary_node.map_input(
        input_variable="det_total",
        expression="flow.check_deterministic.output.total",
        default_value="0",
    )
    summary_node.map_input(
        input_variable="agent_findings_json",
        expression="flow.rule_rag_check.output.agent_findings_json",
        default_value="[]",
    )

    # ⑤ 担当者レビュー（User Activity: ⑤-a 結果表示 → ⑤-b 承認/差戻しフォーム）
    review_activity = aflow.userflow()
    review_activity.spec.display_name = "⑤ 担当者レビュー"

    # ⑤-a: 一次チェック結果の表示
    result_display = review_activity.field(
        direction="output",
        name="check_result_display",
        display_name="一次チェック結果",
        kind=UserFieldKind.Text,
        text="{flow.build_summary.output.final_summary}",
    )

    # ⑤-b: 承認 / 差戻しフォーム
    review_form = review_activity.form(
        name="review_form",
        display_name="承認 / 差戻し",
        submit_button_label="送信",
    )
    choices_map = DataMap()
    choices_map.add(Assignment(
        target_variable="self.input.choices",
        value_expression='["approved", "rejected"]',
    ))
    review_form.single_choice_input_field(
        name="review_decision",
        label="判断",
        required=True,
        choices=choices_map,
        show_as_dropdown=True,
        placeholder_text="承認 / 差戻しを選択してください",
    )
    review_form.text_input_field(
        name="review_comment",
        label="コメント（差戻し理由など）",
        required=False,
        single_line=False,
        placeholder_text="差戻しの場合は理由を記載してください",
    )

    review_activity.edge(START, result_display)
    review_activity.edge(result_display, review_form)
    review_activity.edge(review_form, END)

    # ⑥ フロー出力の明示的マッピング
    collect_output = aflow.script(
        name="collect_review_output",
        display_name="⑥ レビュー結果収集",
        script=(
            "self.output.check_summary   = flow.nodes['build_summary'].output.final_summary\n"
            "self.output.review_decision = flow.nodes['review_form'].output.review_decision\n"
            "self.output.review_comment  = flow.nodes['review_form'].output.review_comment"
        ),
        output_schema=FlowOutput,
    )

    aflow.sequence(
        START,
        extract_node,
        det_node,
        agent_node,
        summary_node,
        review_activity,
        collect_output,
        END,
    )
    return aflow

Step 8: 評価

指標測定方法
指摘再現率熟練者の過去チェック結果と突合
指摘適合率AI 指摘に対する熟練者の妥当性判断
引用精度出典条項の正しさ。回答本文の条文番号を手動検証し、Conversations のエクスポートで一括収集する。Usage Analytics の Citation Accuracy は公式ガイド記載の指標だが、検証環境（v1.4.3）では確認できなかったため、利用環境で提供されている場合に併用する
決定論的チェックの再現性同一入力の反復実行で 100% を確認
処理時間文書 1 件あたりの所要時間

担当者の判断結果は会話エクスポート（Conversations）と合わせて記録し、規約・辞書・事例の更新にフィードバックします。

注意事項

  • 入力文書に個人情報や機微情報が含まれる場合は、送信前の匿名化と、SaaS へ送信するデータ範囲の合意が必要です。
  • AI は一次チェックと根拠提示に限定し、最終判断は担当者が行います。

文書アップロードによる取り込み

ローカル文書ファイルを ContentIQ に取り込む
最終更新: 2026/9/18

概要

規約や基準文書など、ファイルとして管理されているコンテンツを取り込む最も基本的な方法です。最初はこの方法から始めることを推奨します。

ポイント
wxO に登録されるツールは、取り込みを実行したユーザーの情報で ContentIQ に接続します。そのユーザーのアカウントが削除されるとツールが動作しなくなるため、本番用の取り込みはサービス用アカウントで行ってください（セキュリティと RBAC 参照）。

手順

Document Upload は 4 ステップのウィザードで進みます。

  1. 左サイドバーの Connections → Document Upload を開きます。
  2. Step 1: Upload Files — Select Files でファイルを選択し、Continue をクリックします。
    • 対応形式（画面表示）: PDF、DOC/DOCX、Outlook (.msg)、PowerPoint (.ppt/.pptx)、HTML、テキスト (.txt)、Markdown、CSV、Excel (.xls/.xlsx)
  3. Step 2: Choose Agent Type — 対象エージェントの方式を選び、Continue をクリックします。
    • Use Existing Agent — 既存の wxO エージェントにナレッジを付与（推奨）
    • Create New Agent — ContentIQ から新規に wxO エージェントを作成
  4. Step 3 — Step 2 の選択によって内容が変わります。
    • Use Existing Agent の場合: Select an Existing Agent で wxO のエージェント一覧から対象を選びます。一覧は検索ボックスで絞り込めます
    • Create New Agent の場合: Name Your New Agent で Agent Name（必須）と Agent Description（任意）を入力します。取り込み完了時に、この名前で wxO エージェントが作成されます

  1. Step 4: Confirm Ingestion Settings — 設定内容を確認し、Finish & Connect をクリックすると取り込みが始まります。
    • Notify Email Upon Completion — 完了時のメール通知（複数宛先も指定可）。通知は no-reply@symplistic.ai から届きます
    • Enable Table Extraction — 文書内の表を抽出して取り込む

ポイント
Step 3 の一覧には、接続した wxO インスタンス上のエージェントがすべて表示されます。名前が似ているエージェントが多い場合は検索ボックスで絞り込んでください。
表を含む文書の取り込みについて
実機検証（v1.4.3、表を 5 つ含む 2 ページの PDF）では、Enable Table Extraction の ON / OFF でチャンク数や Structured Data Overview に差はなく、表のセル単位の値（行と列の交差で決まる値）を問う質問では ON / OFF とも安定した回答は得られませんでした。行単位で完結する情報は ON / OFF とも正しく回答できました。表の値を確実に参照させたい場合は、表を CSV / Excel として別途取り込む（構造化データとして SQL 系検索の対象になる）か、行を文章に展開してから取り込むことを推奨します。Enable Table Extraction が有効に働く文書種別や条件については、IBM 担当またはパートナー担当にお問い合わせください。

取り込み時の注意点

公式ユーザーガイドおよびリリースノートに基づく注意点です。

  • OCR: 非テキスト PDF（スキャン画像）は、取り込み前にテキスト層を付与してください。ContentIQ 自体は OCR を行いません。
  • バージョニング: 同名ファイルを再アップロードすると最新版が有効になり、履歴は分析用に保持されます。
  • 見出し構造: 明確なタイトルと見出しは、チャンキングと検索精度を向上させます。規約文書は条項単位で見出しを付けることを推奨します。
  • 日本語: 日本語コンテンツには日本語埋め込みが自動適用されます（v1.2.1 以降）。追加設定は不要です。
  • 構造化データ: CSV / Excel / JSON / XML / Parquet は構造化データとして取り込まれ、SQL 系のハイブリッド検索で処理されます。日本語の構造化データは v1.3.0 以降で対応しています。
  • 取り込み内容の修正: 「チャンク単位の編集とバージョン履歴」は v1.4.4 で追加された機能のため、v1.4.3 の検証環境では利用できません。v1.4.4 以降の環境で利用できます（公式ドキュメントの記載による）。チャンクの切れ方を直したい場合は、Content Management で該当ソースを削除し、文書側の見出し構造を整えてから再取り込みしてください。

Headless API による取り込み

バッチ処理や CI から取り込む場合は、Headless API を利用できます。ここでは 1 ファイルを既存の wxO エージェントに取り込む手順を示します。

事前に用意するもの

項目取得元
ContentIQ API キーSettings → ContentIQ API → Generate（Headless API 参照）
agent_id対象 wxO エージェントの ID。Content Management または Usage Analytics で確認できます
取り込む文書テキスト層のある PDF / DOCX 等。まずは 1 ファイルで試します
実行環境curl が使える端末
ベース URLSaaS の場合は https://backend.contentiq.symplistic.ai。自己ホスト版（OpenShift 等）の場合は、UI と同じホスト（実機確認済み）

手順

  1. 変数を設定します。
export CIQ_BASE="https://backend.contentiq.symplistic.ai"   # 自己ホスト版では自インスタンスのバックエンド URL
export CIQ_API_KEY="<ContentIQ API キー>"
export AGENT_ID="<wxO エージェント ID>"
  1. 取り込みを実行します。
curl -sS -X POST \
  "${CIQ_BASE}/api/headless/document/ingest" \
  -H "Authorization: Bearer ${CIQ_API_KEY}" \
  -F "files=@guideline.pdf" \
  -F "agent_id=${AGENT_ID}" \
  -F "agent_name=My Agent" \
  -w "\nHTTP %{http_code}\n"
  • 複数ファイルは -F "files=@a.pdf" -F "files=@b.pdf" のように繰り返します
  • 成功時は HTTP 202（受付）と、以下の JSON が返ります（実機確認済み）
{
  "agent_id": "<wxO エージェント ID>",
  "file_types": {"documents": 1, "structured_data": 0},
  "ingestion_run_id": "<run の ID>",
  "message": "Processing started: 1 document files (extraction/embedding)",
  "status_tracking_warning": null
}
  • ingestion_run_id を次のステップで使います
  • agent_name は表示用のラベルで、既存エージェント名と一致していなくても受け付けられます
  1. 取り込み状況を SSE で追います。-N でバッファリングを無効にすると、イベントが逐次表示されます。
curl -sS -N \
  "${CIQ_BASE}/api/headless/document/status/<ingestion_run_id>/stream" \
  -H "Authorization: Bearer ${CIQ_API_KEY}"

各イベントは data: {…} の形式で、その時点の run の全状態（差分ではありません）を含みます。status が completed または失敗になるとストリームは閉じます。主なフィールドは以下のとおりです（実機確認済み）。

フィールド内容
run_idrun の ID（受付応答では ingestion_run_id）
statusprocessing → completed。失敗時は is_failed: true
current_stage現在の段階（embedding documents、uploading tool、complete 等）
documents_processing_status / chunking_status / vectorizing_status / database_upload_status / upload_wxo_tool各段階の状態（Pending / In Progress / Complete）。UI のステータスページの 5 段階に対応
total_documents / documents_processed_count / chunked_documents_count / vectorized_chunks / uploaded_vectors / tool_updates各段階の件数
processed_documents[]文書ごとの結果。失敗時は failure_reason と failure_solution に原因と対処が入ります
is_paused / is_aborted / cancel_requested一時停止・中止の状態
total_time経過秒数

参考
実機検証では、PDF 1 ファイル（101 チャンク）の取り込みに約 8 分かかりました。完了の判定は status と current_stage（および各段階の状態フィールド）で行い、埋め込みカバレッジなどの集計値は Ingest Analytics 画面で確認してください。

  1. 結果を確認します。
    • Ingest Analytics で成功率と埋め込みカバレッジを確認
    • Chat Playground で対象エージェントを選び、取り込んだ文書に関する質問をして出典カードを確認
    • 必要に応じて Content Management でチャンクを確認・編集

エラー時の確認

HTTP意味対処
401API キーが無効または未送信、または送信先が別インスタンスまず CIQ_BASE が自分の環境のバックエンドを指しているか確認（自己ホスト版のキーを SaaS のバックエンドに送ると 401 になります）。次に Generate で再生成した直後のキーで再実行
400Missing agent IDagent_id は必須です。Headless API による取り込みは既存エージェント専用です
409同じエージェントで取り込みが実行中完了を待って再実行
429プランのレート制限超過リクエスト頻度を調整

注意
文書アップロード（document ソース）はスケジュール取り込みの対象外です（API は 501 を返します）。定期更新が必要な場合は SharePoint / OneDrive 等のクラウド・ストレージ経由で取り込んでください。
Headless API では agent_id が必須で、省略すると 400 Missing agent ID が返ります（実機確認済み）。ContentIQ 側で新規 wxO エージェントを作成するには、UI のウィザードで Create New Agent を選択してください。

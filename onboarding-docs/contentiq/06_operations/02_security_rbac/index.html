セキュリティと RBAC

ContentIQ SaaS のセキュリティ構成とアクセス制御
最終更新: 2026/9/18

本ページは ContentIQ 公式ユーザーガイドの Governance, Security & Compliance（英語） の SaaS 向け記載を要約したものです。自己ホスト版（OpenShift 等にインストール）では、以下の暗号化・ベクトル DB・オブジェクト・ストア・ログ保持の構成はインストール時の設定に依存し、その統制は顧客責任となります。データ居住の要件がある場合は、自己ホスト版を目的のリージョン（例: IBM Cloud 東京）に配置する構成が選択肢になります。

暗号化

対象保存時転送時備考
MongoDB（メタデータ、会話、ログ）AES-256-GCMTLS 1.3API キーは Fernet で暗号化、パスワードは bcrypt でハッシュ化
ベクトル DBAES-256（SaaS 既定）TLSZilliz Cloud、Qdrant、Azure をサポート
オブジェクト・ストアAES-256（SaaS 既定）TLSAWS S3、Azure Blob

顧客が自身のベクトル DB やストレージを指定する構成も可能ですが、その場合のセキュリティ統制は顧客責任になります。実機（v1.4.3、自己ホスト版）では Settings → Vector Store で Milvus の URI とトークンを、Settings → Object Store で Storage Provider（Default / Azure Blob Storage）を指定できました。他のプロバイダー（公式ガイド記載の AWS S3 等）の利用可否は利用環境で確認してください。

認証

  • IBM Broker 認証（JWT RS256、JWKS 検証、CRN 検証）
  • Azure Entra ID SSO（OAuth 2.0 認可コード・フロー + PKCE、ドメイン許可リスト）
  • ユーザー名 / パスワード（bcrypt）
  • Headless API キー（64 文字、ハッシュ化して保存、テナント分離）

MFA は Entra 側で有効化した場合に SSO 経由で適用されます。

RBAC

  • テナントごとのカスタム・ロールを作成・割り当て
  • ロール割り当ては MongoDB、Milvus、オブジェクト・ストアに同期
  • SSO 設定と RBAC 管理は管理者専用（Administrative Settings の SSO Configuration / Role Settings / Account Assignments / Default Role Settings）
  • コンテンツの可視性はロールに基づく。ソース（文書・サイト）単位で Content Management の Manage Access からロール（Administrator / Member）を指定でき、未指定の場合はテナント既定値を継承する（実機確認済み）
  • SharePoint のファイル権限は取り込み時にチャンクへ付与され、Entra SSO 付き展開の検索時に照合される

監査ログ

  • アプリケーション・ログの保持期間は既定 365 日（変更可）
  • 会話は暗号化して保存され、Conversations 画面から CSV / PDF でエクスポート可能（公式ガイドは CSV / JSON と記載。実機 v1.4.3 では CSV / PDF）
  • 取り込み、管理操作（ロール更新、コンテンツ管理）、認証失敗、セッション作成 / 削除をログ
  • Administrative Settings の Client-Side Audit Trail は、主要な管理操作をブラウザ側にローカル記録する機能で、サーバー側の監査ログを補完する位置づけです（Clear Log で消去可）。監査目的にはサーバー側のログと Conversations のエクスポートを使用してください

wxO に登録されるツールの接続情報

ContentIQ が wxO エージェントに追加するツール（symplisticai_tool_…）は、接続先と認証情報をツール定義内に保持しており、入力パラメーターやコネクターとしては公開されません。ツール定義には取り込みを実行した ContentIQ ユーザーの情報が含まれ、ツールはその情報を使って ContentIQ の文書情報を検索します。運用上は以下に留意してください。

  • 取り込みは個人アカウントではなく、サービス用アカウント（共有アカウント）で行う。取り込みを実行したユーザーのアカウントが ContentIQ から削除されると、そのユーザーが登録したツールは動作しなくなります
  • 取り込みを実行したアカウントを削除する必要がある場合は、事前に提供元（symplistic.ai）またはサポートに、ツールの接続を別アカウントへ引き継ぐ手順を確認してください
  • ツール定義の閲覧・エクスポート権限は wxO 側のアクセス制御で管理する
  • ContentIQ の API キー（Settings → ContentIQ API）は Headless API 用であり、wxO に登録済みのツールの認証には使われないと考えられます。影響の有無については IBM 担当またはパートナー担当にお問い合わせください

元ファイルの保持

既定では、ContentIQ は取り込んだソース・ファイルを処理して検索用のチャンクとメタデータを生成した後、元ファイルを保持しません（永続オブジェクト・ストレージを明示的に構成した場合を除く）。保持されるのは以下です。

  • ベクトル埋め込みとチャンク化されたコンテンツ（構成したベクトル DB 内）
  • 検索・権限・出典表示に必要なメタデータ
  • 運用監視用の処理ログ

自己ホスト版では、元ファイルの保持はインストール先のストレージ構成に従います。機微な文書を扱う場合、この既定動作（元ファイル非保持）は保持データを最小化する観点で有利ですが、逆に元ファイルの再取得が必要な運用では別途保管が必要です。

Widget の外部配信元

Widget 方式で展開する場合、ローダー JS と iframe は symplistic.ai の配信サービス（https://contentiq-widget.pages.dev）から提供されます（自己ホスト版でも同様。実機確認済み）。閉域網や外部通信を制限する環境では、この配信元への到達性と CSP の許可が必要です。自環境内で完結させたい場合は External Agent 方式（自インスタンスのホスト配下）を使用してください。

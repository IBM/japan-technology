Headless API と MCP

wxO フローや外部システムから ContentIQ を呼び出す
最終更新: 2026/9/18

API キーの取得

wxO の API キーとは別に、ContentIQ 自身の API キーを発行します。

  1. ContentIQ にログインします。
  2. 左サイドバーの Settings → ContentIQ API タブを開きます。
  3. Generate をクリックします。
  4. 表示されたキーを Copy で控えます。

注意
キーは生成時にのみ表示され、後から再表示できません。安全な場所に保管してください。
Generate を再度実行すると、既存のキーはすべて無効になります。wxO に登録済みの ContentIQ ツールは取り込みユーザーの情報で認証するため、この API キーの再生成による影響は受けないと考えられます。影響の有無については IBM 担当またはパートナー担当にお問い合わせください（セキュリティと RBAC 参照）。
API Key Statistics の Keys remaining に、生成できる残り回数が表示されます。上限に達した場合は IBM 担当またはパートナー担当にお問い合わせください。

レート制限

プラン上限
Starter50 req/min
Essentials100 req/min
Standard150 req/min
Premium200 req/min

超過時は HTTP 429 が返ります。

認証は Authorization: Bearer <API_KEY> です。ベース URL は提供形態によって異なります。

チャットの例

curl -X POST "${CIQ_BASE}/api/headless/chat" \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer YOUR_API_KEY_HERE" \
  -d '{
    "agent_id": "your-agent-id",
    "message": "年次有給休暇の付与条件を教えてください。根拠となる箇所も示してください。",
    "thread_id": "report-check-0001"
  }'

agent_id は wxO の Agent ID です（エージェント ID の確認 参照）。

応答は以下の形式です（実機確認済み）。

{
  "agent_id": "<エージェント ID>",
  "response": "<回答本文>",
  "response_time": 31.9,
  "thread_id": "<スレッド ID>",
  "timestamp": "2026-09-10T15:28:59Z"
}
  • response は文字列です。エージェントの指示で JSON 出力を指定している場合も、JSON 文字列として格納されるため、利用側でパースします
  • response_time は秒、timestamp は UTC です
  • 実機では 1 回の応答に約 30 秒かかりました（wxO エージェント経由の回答生成）

thread_id の生成と管理

thread_id は会話（スレッド）を識別する文字列です。呼び出し側で指定するか、省略してサーバーに発行させます。ContentIQ はこの ID 単位で会話履歴を保存し、同じ thread_id で続けて呼び出すと前の発話を文脈として扱います。

観点内容
生成方法呼び出し側で一意な文字列を生成して指定するか（UUID v4 を推奨）、省略してサーバーに発行させます
単位1 つの会話セッションにつき 1 つ。フォローアップの質問は同じ thread_id を再利用し、新しい話題や別の利用者では新しい ID を発行します
スコープagent_id と thread_id の組で識別されます。同じ thread_id を別のエージェントに使っても履歴は共有されません
履歴の取得・削除GET /api/headless/conversations/<agent_id>/<thread_id> で取得、DELETE で削除できます
UI との対応Headless API で作成したスレッドも Conversations 画面に表示され、CSV / PDF でエクスポートできます
省略時の挙動サーバーが UUID を発行し、応答の thread_id で返します（実機確認済み）。フォローアップではその値を再利用します。業務 ID と紐付けたい場合は呼び出し側で指定します
形式・長さの制約、保持期間公式ドキュメントに記載がありません。必要な場合は IBM 担当またはパートナー担当にお問い合わせください

業務システムから呼び出す場合の設計例

業務システムから呼び出す場合、1 件の処理が 1 つの会話に対応するなら、業務側の ID を含めた thread_id（例: <業務種別>-<文書番号>-<日付>）を使うと、Conversations の履歴と業務レコードを突き合わせやすくなります。ただし、thread_id は URL パスに含まれるため、URL に使えない文字や機微な情報（個人名など）は含めないでください。

# 例: 処理 1 件につき 1 スレッド
export THREAD_ID="doc-$(date +%Y%m%d)-$(uuidgen | tr 'A-Z' 'a-z' | cut -c1-8)"
curl -sS -X POST "${CIQ_BASE}/api/headless/chat" \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer ${CIQ_API_KEY}" \
  -d "{\"agent_id\": \"${AGENT_ID}\", \"message\": \"（質問）\", \"thread_id\": \"${THREAD_ID}\"}"

# 同じスレッドの履歴を取得
curl -sS "${CIQ_BASE}/api/headless/conversations/${AGENT_ID}/${THREAD_ID}" \
  -H "Authorization: Bearer ${CIQ_API_KEY}"

wxO フローから呼び出す

wxO のフローやツール（OpenAPI ツール、Python ツール）から Headless Chat API を呼び出すことで、定型的な業務処理に ContentIQ の根拠回答を組み込めます。構成例は ユースケース例 を参照してください。

MCP 統合

検証状況
MCP 統合は v1.4.4 で追加された機能で、公式ドキュメントの記載に基づいています。v1.4.3 の検証環境では利用できず、未検証です。

v1.4.4 で Model Context Protocol による接続が追加されました。承認された AI クライアントから ContentIQ のエージェントとワークフローを操作できます。詳細は ContentIQ MCP Integration（英語） を参照してください。wxO 側の MCP ツール設定と組み合わせる手順は本ガイドでは扱いません。
